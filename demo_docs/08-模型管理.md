# 模型管理

一句话：**先看目录挑模型 → 下载 → 用中文备注写清用途 → 设一个默认**。界面（快捷键 `M`）和命令行 `autolabel models` 管的是同一份数据，任何一边改了另一边立刻生效。

管的三类东西：

- **姿态权重（YOLO-pose）**：内置 13 档可下载目录（YOLO11 / YOLOv8 / YOLO26 的 n~x），加上自己放进 `models/` 的自定义权重。
- **本地登记的模型**：放在仓库外任意路径的权重，只记路径和说明，文件不搬动。
- **多模态大模型**：本地（Ollama / LM Studio / vLLM）或云端（OpenAI / 通义千问）服务配置。

## 界面上在哪

模型管理是四个页面里的一个，壳层和其他页一模一样：左侧竖排导航条直接跳工作台 / 姿态标注 / 提示词标注；顶栏 `⌘K` 命令面板能搜「下载」「设为默认」「去复核」；`?` 打开本页说明；**重新读取权重**收在右上角 `⋯` 里（快捷键 `R`），当前默认模型也显示在同一个菜单顶部。

## 一句话速查

| 想做什么 | 命令行 | 界面「模型管理」 |
| --- | --- | --- |
| 浏览可下载模型 + 中文说明 | `models --browse` | 「模型目录」区块，每行带说明、参数、体积、关键点、适合场景 |
| 看单个模型详情 / 下载地址 / SHA256 | `models --info yolo11m-pose` | 目录行展开的 meta 行 |
| 下载 | `models --download-weight yolo11l-pose.pt` | 行内「下载」按钮，进度实时显示 |
| 写备注 | `models --note yolo11l-pose=只在内网机下` | 行内备注输入框 + 「保存备注」 |
| 清空备注 | `models --note yolo11l-pose=` | 输入框清空后保存 |
| 设默认 | `models --default yolo11m-pose` | 行内「设为默认」 |
| 登记仓库外的权重 | `models --register ~/w/my.pt --display-name 棚内权重` | 底部「登记本地模型」三个输入框 |
| 取消登记 | `models --forget my` | 行内「取消登记」 |
| 只看重活多模态 | `models --capability vlm` | 顶部筛选下拉框 |
| 判能不能用在当前数据集 | `models --dataset datasets/demo` | 目录行直接写明不兼容原因 |

命令行都写成 `python3 -m autolabel models ...`。

## 数据落在哪四个地方

| 位置 | 内容 | 建议 |
| --- | --- | --- |
| `models/*.pt` | 权重本体 | 不入库，随时可删可重下 |
| `configs/models.json` | 模型登记表：备注、默认模型、本地登记路径、下载记录、最后使用时间、加载实测元数据 | 不入库（纯本机状态，删了不影响标注结果） |
| `configs/vlm.json` | 多模态服务配置：地址、模型名、超时、回复上限、送图最长边、JSON 模式、备注 | 里面**没有** API Key 明文 |
| `~/.autolabel/secrets.json` | API Key 明文（权限 0600），配置里只留 `vlm:<配置ID>` 引用 | 不在仓库里 |

可用环境变量改路径：`AUTOLABEL_WEIGHTS_DIR`、`AUTOLABEL_MODEL_CONFIG`、`AUTOLABEL_VLM_CONFIG`、`AUTOLABEL_SECRETS`、`AUTOLABEL_WEIGHTS_MIRROR`（权重下载镜像，留空回到 GitHub 直连）。

老配置里如果还残留明文 `api_key`，第一次读 `configs/vlm.json` 时会自动搬进 Key 文件并把配置改写成 `key_ref`，不用手工处理。

## 浏览目录：`--browse`

```
可下载模型目录（13 个）：先在这里挑，再下载，未下载的模型不能在上传弹层里直接选

yolo11n-pose      YOLO11-nano 姿态                  2.9M 参数         预计 6.0 MB
  说明：最小的姿态权重，下载快、显存占用低，适合先跑通流程和大批量抽帧预筛。精度是 YOLO11 这一代里最低的，小人和重叠关节点容易漂。
  适合：试跑验证、大批量预标注、CPU 或轻薄本 ｜ 速度：最快，CPU 也能实时 ｜ 关键点：17 个（COCO-17） ｜ 精度：2.9M 参数，mAP50-95 约 50.4
  下载：python -m autolabel models --download-weight yolo11n-pose.pt
```

目录顺序即界面顺序，前三档（YOLO11 的 n/s/m）是推荐的默认档，也是上传弹层下拉框的默认候选。YOLO26 三档官方暂未公布参数规模与 mAP，说明里直说「官方暂未公布」，不当主力用。

不带参数是分组清单（含每档状态、体积、最后使用、备注）：

```
姿态估计（YOLO-pose，快且稳）
模型 ID           中文名                状态        体积          最后使用            备注 / 提示
yolo11n-pose      YOLO11-nano 姿态      可用        6.0 MB        -                   默认
yolo11l-pose      YOLO11-large 姿态     未下载      约 50.7 MB    -                   -
```

`--info <模型ID>` 是竖排详情，含本地路径、实际/预计体积、参数、精度、关键点集、速度、适合场景、是否默认、最后使用、兼容性、备注、下载地址、SHA256，以及最近 3 条下载记录。

## 下载与下载记录

`--download-weight` 已就绪就跳过，`--force` 强制重下；界面点「下载」等价，同名任务不会重复起线程。下载经镜像（默认 `https://gh-proxy.com/`），支持断点续传，先写 `*.pt.part`，长度与 zip 完整性都过了才改名，失败自动重试。

每次下载都在登记表里留一条记录（最多留 50 条）：`model_id` / `name` / `url` / `mirror` / `sha256_expected` / `sha256_actual` / `sha256_match` / `expected_bytes` / `bytes` / `size_mb` / `temp_name` / `seconds` / `ok` / `error` / 起止时间。

- 目录里有官方 SHA256 的档位（n/s/m 等）会顺带核对；**不一致只提示「建议删除后重下」，不判失败**，因为镜像偶发的体积正常但内容不一致值得人工看一眼。
- 官方没公布 SHA256 的档位不下结论，只记体积与结果。
- `models --info <ID>` 会列出该模型最近 3 条记录。

## 备注说明

给模型写一句人话，避免下次猜「这个权重当初为什么下的」。

```bash
python3 -m autolabel models --note yolo11l-pose=只在内网机器下，本机显存吃紧
python3 -m autolabel models --note yolo11n-pose=            # 等号后留空即清空
```

- 支持重复 `--note`，一次写多个；ID 写模型 ID 或权重文件名都认（`yolo11n-pose` 与 `yolo11n-pose.pt` 同一个）。
- 上限 500 字，超长截断；存在 `configs/models.json` 的 `notes` 里。
- 多模态配置的备注沿用配置里的 `remark` 字段，界面两处看到的是同一句话。
- 未知 ID 直接报错并提示用 `--browse` 查目录，不会静默新建。

## 默认模型与本地登记

`--default <ID>` 按能力分别记默认值（pose / vlm / custom_task 互不影响），界面标「默认」。没显式设过时的兜底顺序：已就绪的推荐档 → 任一已就绪的 → 目录第一档，保证上传弹层永远有得选。跨能力设默认会被拒（拿姿态权重当多模态默认属于填错）。

```bash
python3 -m autolabel models --register ~/weights/gym.pt --display-name 体操自研 --note gym=只标体操视频
python3 -m autolabel models --forget gym
```

- 登记只写路径与说明，文件不动；`--forget` 只删登记条目，文件留原地。
- 姿态类要求文件是完整 zip 结构的权重包，半截文件当场拒绝（避免把下载失败的东西登记进来）。
- 文件名本来就落在内置目录里（如 `yolo11n-pose.pt`）不会重复登记，只把说明写成备注，并提示直接用 `--note`。
- ID 默认取文件名（去扩展名），`--id` 可改；撞上已有 ID 且指向不同文件会报错，让你换名字。
- 内置目录里的档位**不能** `--forget`（文件可以删），提示改用备注或在登记表 `catalog.<ID>.hidden` 里隐藏。

## 兼容性怎么判的

带 `--dataset` 时（界面打开复核页时自动带上），每个模型会和当前数据集比对：

- 目录标题的计数按能力分开写：`共 15 个 · 姿态权重就绪 6/13 · 多模态配置可用 2/2`。姿态权重的「就绪」= 权重文件已下全且校验通过；多模态配置的「可用」= 连接信息完整且最近一次连通性测试通过，两件事不是一回事，所以不合并成一个数字。
- 关键点数量不一致 → 状态「不兼容/暂不可用」，理由写清「当前数据集 X 是 17 关键点，该模型输出 26 关键点（COCO-26），标出来的骨骼没法直接和已有标签合并」。
- 权重文件不完整（半截、损坏）→ 不兼容，提示删掉重下。
- 多模态配置没做过连通性测试 → 提示先点「保存并测试」；最近测试失败 → 状态不可用并带上失败原因。

模型加载时还会把实测元数据（真实关键点数、设备、ultralytics 版本、输入尺寸）回写进登记表，`--info` 里以「加载实测」显示，兼容性问题不靠猜。

## 状态与来源术语

| 状态 | 含义 |
| --- | --- |
| 可用 | 文件完整（权重通过 zip 完整性校验）；多模态则代表最近一次连通性测试通过 |
| 未下载 | 目录里有这条，但本地没有文件；体积列显示预计值 |
| 文件不完整 | 有文件但不是完整权重包，通常是下载中断或损坏，删掉重下 |
| 不兼容/暂不可用 | 文件可用但用不通：关键点数量对不上，或多模态测试失败 |

| 来源 | 含义 |
| --- | --- |
| 内置目录 | 只在目录里登记、本地还没有文件 |
| 已下载 | 经本项目下载得到的本地权重 |
| 本地 | 自己拷进 `models/` 或用 `--register` 登记的模型 |
| 外部服务 | 多模态的云端 API 配置 |

## 多模态大模型

字段、预设与连通性验证见 `02-命令行参考.md` 的「多模态大模型配置」。这轮新增三个运行参数，按服务算力调：

| 参数 | 默认 | 作用 |
| --- | --- | --- |
| 回复上限 `max_tokens` | 4096 | 思考型模型把额度花在推理上，太小会回空正文 |
| 送图最长边 `image_limit` | 1024 | 压小图片能显著省 token 与时间，细节多的画面可调大 |
| 强制 JSON 模式 `json_mode` | 关 | 端点支持 `response_format` 时打开，少一大类解析失败 |

命令行写法：

```bash
python3 -m autolabel models --add-vlm '{"name":"本地 Ollama","provider":"ollama","model":"qwen2.5vl:7b","max_tokens":2048,"image_limit":768}'
python3 -m autolabel models --test-vlm vlm_a13bdd38
```

## 界面里注意什么

- 「模型目录」区块可以按能力筛选（全部 / 姿态 / 多模态），右上角写明「共 N 个 · 可用 M 个」。
- 未下载的模型在上传弹层的模型下拉框里是灰的（点不动）；一个都没下载时放开第一条，点了会先下再标。
- 选了模型后上传弹层里会有一行中文说明，写这档适合什么、精度大概多少，不用来回切面板。
- 「取消登记」按钮只对登记进来的本地模型出现，内置档位没有这个按钮。
- 面板底部会写明登记表、权重目录、Key 文件的实际路径，换机器时该拷哪份一目了然。

## 常见操作

```bash
# 只看当前数据集能用的姿态模型
python3 -m autolabel models --capability pose --dataset datasets/demo

# 一次给三档写备注 + 设默认
python3 -m autolabel models \
  --note yolo11n-pose=预筛用 \
  --note yolo11m-pose=主力 \
  --default yolo11m-pose

# 机器迁移：登记表和 Key 文件一起带走，配置不带 Key
cp configs/models.json <新机> && cp ~/.autolabel/secrets.json <新机>/.autolabel/

# 程序化读取（给脚本用）
python3 -m autolabel models --json | head -50
```
