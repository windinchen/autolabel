# 命令行参考

统一入口：`python3 -m autolabel <命令>`。所有命令的第一个参数都是数据集目录。

| 命令 | 作用 | 关键参数 |
| --- | --- | --- |
| `init` | 建数据集骨架（素材池 `images/` + 三库标签 `labels/ prompt_labels/ detect_labels/` + 各自的索引/批次/备份） | `--name` `--class-names` `--num-keypoints` |
| `import` | 导入图片：规范化 RGB、展开 EXIF 旋转、限最长边、去重；素材已在池里就直接复用 | `--lib pose/objects/detect` `--dedupe none/exact/perceptual` `--max-side` `--subdir` `--batch-name` |
| `video` | ffmpeg 抽帧导入，帧上记录 `time_sec` / `frame_index` | `--lib pose/objects/detect` `--fps` `--scene` `--max-frames` `--start` `--duration` `--batch-name` |
| `auto` | 一条命令：导入/抽帧 → 标注 → QC → 坐标导出；`--lib objects/detect` 时只入库并收尾（这两个库不跑 YOLO-pose） | 上述导入参数（含 `--lib`）+ 全部标注参数 + `--formats` `--coords-out` `--batch-name` |
| `label` | 批量自动标注，支持断点续跑 | `--model` `--extra-models` `--device` `--imgsz` `--conf` `--no-flip` `--force` |
| `qc` | 质量报告、复核优先级清单、骨架叠加图 | `--top` `--render` `--render-all` `--include-reviewed` `--json` |
| `review` | 浏览器复核界面（含导入素材、下载坐标），默认走本地 HTTPS | `--port` `--no-browser` `--max-upload-mb` `--device` `--half` `--no-ssl` |
| `ca` | 本地 HTTPS 证书：签发 + 设为受信任（摄像头要 HTTPS，一台机器做一次） | `--status` `--force` `--no-install` `--uninstall` |
| `export` | 导出训练数据集（train/val + `data.yaml`；val 成员按路径哈希定，重导不换人） | `--val-ratio` `--coco` `--coords` `--mode symlink/copy/hardlink` `--only-approved` |
| `coords` | 只导出坐标文件 | `--formats csv,long,jsonl` `--only-approved` `--include-all` `--include-unlabeled` |
| `validate` | 校验标签格式、关键点数量、孤儿标签；**三个库都查**，还比对索引里的框数与磁盘标签 | `--lib all/pose/objects/detect` `--num-keypoints` |
| `status` | 数据集概览（三个库各自进度 + 素材池占用 + 状态/框高分布 + 标注参数） | — |
| `batches` | 按批次列出三个模块的标注数据，整批或按张删除图片与记录 | `--lib all/pose/objects/detect` `--delete <批次ID>`（可重复） `--delete-images images/a.jpg`（可重复） `--mode lib/purge` `--keep-files` `--force` `--json` |
| `pool` | 看共享素材池（每张图被哪几库引用），把池里已有的图认领进某个库 | `--add images/a.jpg`（可重复） `--lib pose/objects/detect` `--limit` |
| `migrate` | 把旧版单索引数据集拆成姿态库 + 提示词库（幂等，复核服务启动时自动做；目标检测库首次使用时自动建） | — |
| `fields` | 管类别表：提示词库的字段名 + 描述提示词，目标检测库的类别名 + 中文名 | `--add 字段名=描述` `--set-label 字段名=显示名` `--delete 字段名` `--drop-boxes` `--lib objects/detect` `--json` |
| `prompt` | 提示词标注：让多模态大模型按字段描述找物品，产出 YOLO detection 框 | `--fields` `--vlm` `--limit` `--overwrite` `--prompt-extra` `--coords` `--export` `--status` |
| `detect` | 目标检测：用本机 YOLO 检测/分割/旋转框权重批量出框，先选权重再勾权重认识的类别 | `--model` `--list-models` `--model-classes` `--add-classes all` `--no-label` `--classes` `--images` `--overwrite` `--coords` `--export` `--status` |
| `models` | 搜/浏览/下载模型（五种任务）、写中文备注、设默认、登记本地模型、管多模态配置 | `--search` `--task` `--remote` `--browse` `--info` `--note` `--default` `--register` `--forget` `--dataset` `--download-weight` `--delete-weight` `--add-vlm` `--test-vlm` `--json` |
| `reset` | 复核状态退回未复核（状态名拼错当场报错；`--labels` 只删真被退回的那些） | `--lib pose/objects/detect` `--status` `--keep-approved` `--labels` |
| `version` | 看版本号 / 开发者 / 与 GitHub 发布版比对，就地升版本号（不需要数据集目录） | `--check` `--bump patch/minor/major` |
| `settings` | 看 / 改系统设置：推理设备与半精度，附这台机器的算力探测结果（不需要数据集目录） | `--device auto/cuda/mps/cpu` `--half` `--no-half` `--reset` `--json` |
| `launch` | 双击启动器真正的入口（macOS 与 Windows 共用一份逻辑）：自检 → 缺证书现签 → 起服务 → 端口真监听了才开浏览器 | `[dataset]`（默认 `datasets/demo`） `--port` `--host` `--device` `--half` `--no-browser` `--wait` |
| `service` | 常驻服务：注册 / 状态 / 重启 / 注销。macOS 走 launchd，Windows 走任务计划程序，流程只写一份 | `--status` `--restart [名字]` `--remove [名字]` `--dry-run` `--show 名字` `--print-env 名字` |
| `service-run` | 被服务管理器拉起来的那一个实例：无界面、不开浏览器，端口被占就让路退出 0。平时不用手敲 | `[名字]` `--port` `--dataset` `--device` `--half` `--wait` |

## 行为要点

- **断点续跑**：`label` / `auto` 给每张图记参数指纹 `label_signature`，**该不该重标逐张判**：指纹一致的跳过，换了模型或 `--imgsz` 的自动判定过期重标，中断前已经按新参数标好的那些不会被再标一遍。
- **人工结果保护**：状态是 `approved`（点过接受）或 `edited`（手改过骨骼）的图默认**不进重标队列**，模型不会把人工结果盖掉；要连它们一起重标用 `--force`（这时状态退回未复核，得重新过目）。被跳过几张会写在 `label` 的输出里。
- **可见性策略**：`--visibility-policy threshold`（默认，按 `--visible-conf` / `--occluded-conf` 分级）、`all_visible`（全部标 2）、`binary`（只分 0/2）。
- **多模型共识**：`--extra-models a.pt,b.pt`，一致时打 `multi_model_confirmed`，分歧时打 `model_disagreement` 供人工优先看。
- **背景图比例**：空标签是负样本，`export --max-empty-ratio`（默认 0.15）控制占比。被压掉的张数在命令行打印成「剔除明细」，并逐张写进 `manifest.json` 的 `skipped`（原因形如 `背景图超出比例上限（上限 15%）`）；导出目录的 `counts.empty` 是**收进来的**张数，`counts.empty_dropped` 是被压掉的张数。
- **导出符号链接**：`--mode symlink` 省空间，ultralytics 正常跟随。链接写的是**相对路径**（`../../../images/a/frame_0001.jpg`），导出目录在数据集 `exports/` 里时，数据集整体改名、搬家、换挂载点都不会断链；把导出目录单独挪到别的层级仍需重导（相对层级对不上）。只带走导出目录本身时用 `--mode copy`。
- **导出目录里的文件名**：导出目录是平的（只有 `images/train`、`images/val`），子目录会被压进输出名——`a/frame_0001.jpg` → `a__frame_0001.jpg`。以前只取文件名，不同子目录里的同名素材会抢同一个输出名，后放的连图片带标签把前面的盖掉（实测 4 张图导完磁盘只剩 2 个文件，`manifest.json` 与 COCO 里却记 4 张）。素材平铺时输出名一字不变。
- **`data.yaml` 的 `flip_idx` 跟着关键点数走**：17 点用 COCO 标准左右配对；点数更少（自定义 / 裁剪关键点模型）时，配对落到范围外的点改成自己映自己，不再写越界下标（14 点以前会写 `flip_idx: [..., 14]`，而 14 点里没有 14 号点）；点数更多时补齐到同长。
- **模型管理**：`models` 不带参数就是分组清单（姿态权重 + 多模态大模型，含状态、体积、最后使用、备注）。`--browse` 看 13 档可下载目录的中文说明与下载命令，`--info <ID>` 看单个模型详情（含下载地址、SHA256、最近下载记录），`--note ID=说明` 写备注，`--default <ID>` 设默认，`--register` / `--forget` 登记或注销仓库外的权重，`--dataset` 顺带按关键点数量判兼容性。权重只认 `models/` 目录里的裸文件名，删除后下次标注自动经镜像重下；正在被任务使用的权重删不掉。完整说明见 `08-模型管理.md`，多模态配置见下方「多模态大模型配置」。
- **提示词标注**：`fields` 定义"要标什么、怎么向模型描述"，`prompt` 逐张问多模态大模型要检测框，写进提示词库自己的 `prompt_labels/` 与 `.autolabel/objects/index.json`，与姿态库互不覆盖；产出走 `yolo detect train`。完整说明见 `09-提示词标注.md`。
- **`auto --lib objects` / `--lib detect`**：只想批量灌素材给提示词标注或目标检测时用这两条——入库（含抽帧与去重）后直接收尾批次，**跳过 YOLO-pose 标注、QC 与骨骼坐标**（那三段是姿态库的流水线），并打印下一步该跑的 `prompt` / `detect` 命令。
- **三个库、一个素材池**：`--lib pose`（默认）进姿态库，`--lib objects` 进提示词库，`--lib detect` 进目标检测库。三个库的索引、批次表、撤销快照、标签目录（`labels/` `prompt_labels/` `detect_labels/`）全部分开，只有 `images/` 素材池共用——同一帧被几个模块用到都只落盘一次，命令行输出与批次备注里的「复用素材池 N」就是省下的次数。`pool` 命令看池子里都有谁、还差哪个库，`--add` 直接认领（等价于网页上的「从素材池添加」）。目标检测库的索引与类别登记表（`.autolabel/detect/`）在该库第一次用到时自动建，不用手动初始化。
- **`detect` 的类别号由本库登记表决定**：模型自带的编号（COCO 里 `bus=5`）只用来认类别，**写进标签文件的编号来自 `.autolabel/detect/classes.json`**，且同名类别永不换号、删掉的号不回收。这样换权重（yolo11n → yolov8x）时先前标好的框不会一夜之间指错东西，和提示词库的字段号是同一条规则。`--add-classes all` 只登记该权重真报得出的类别，模型不认识的会单独列出来而不是悄悄收进来。
- **删除粒度**：按张删（`--delete-images`）删哪个库由 `--lib` 决定——`--lib pose` 只摘姿态库的引用和标签，另外两个库与 `images/` 里的素材都不动；`--lib all`（**默认**）三个库的引用一起摘，素材文件仍留在池里；`--mode purge` 三个库一起摘**并删掉素材文件**（加 `--keep-files` 只删记录留文件）。整批删（`--delete`）自动判定批次属于哪个库，素材只在其余库都不再引用时才删。输出里那句「三个库都摘 / 仅某库」就是这次真正动过的范围。
- **索引里记着、图却不在了**：`images/` 里的文件被手工删掉之后，`status` 会单列「缺文件 N 张」并点名是哪几张，`validate` 报 `missing_file`，`export` 与 `coords` 直接跳过这些帧（不再产出一根指向空气的软链），导出结果的 `manifest.json` 里记 `missing_source` 计数。放回图片或在库里删掉这些帧即可。
- **框数账目对不上会被查出来**：`validate` 比对「索引里记的框数」与「标签文件里真实的框数」，不一致报 `count_mismatch`；索引写着「没标过」但文件里有框也报（这种帧导出时会整张跳过）。
- **启动对账**：导入/标注跑到一半被打断（重启复核服务、断电、强杀）时，图片副本可能已经落盘但索引没保存。复核服务启动时按磁盘补回这些图片、把无人认领的"标注中"批次判定为中断，并用 `--keep-files` 删除批次的保留文件不会被误当成孤儿重新长出。对账时每个库只解析一次对面库的索引，耗时不随图片数平方增长（实测 1500 张的数据集从约 1 秒降到 0.04 秒）。
- **批次分组**：`import` / `video` / `auto` 与网页上传都会登记一个批次（`--batch-name` 自定义名称），写进所属库自己的批次表：`batches --lib pose` 看姿态库、`--lib objects` 看提示词库、`--lib detect` 看目标检测库，默认 `all` 三库合看（每行标库名与「骨骼 / 检测框」两套进度）。`--delete <批次ID>` 整批删除图片、标签与记录，`--delete-images images/a.jpg`（可重复）按张删除传错的图（批次记录里同步摘除，某批被删空时记录一并移除），删除前都自动快照到 `.autolabel/deleted/`（只保留最近 200 份，留出余量后一次清一批）。「未分组」桶用 `__ungrouped__:pose` / `__ungrouped__:objects` / `__ungrouped__:detect`，裸写 `__ungrouped__` 一次清三个库里所有没分组的图。

## 参数取值范围与报错约定

数值参数在**解析阶段**就当场校验，越过合理范围直接拒绝，不会等流水线跑到一半才暴露（比如标到第 8000 张才发现 `--conf 5` 一个框都不会有，白烧一小时显卡）。

| 参数 | 允许范围 | 备注 |
| --- | --- | --- |
| `--conf` `--iou` `--visible-conf` `--occluded-conf` `--scene` `--val-ratio` | 0~1，**不含**两端 | 阈值与比例；`--conf 5`、`--val-ratio 1.5` 当场报错 |
| `--max-empty-ratio` | 0~1，**可取**端点 | 背景图占比允许填 0（完全不要负样本） |
| `--imgsz` `--max-det` `--max-side` `--max-frames` `--top` `--max-upload-mb` `init --num-keypoints` | 正整数 | `--imgsz 0` 以前会让 YOLO 收到 0 像素输入 |
| `--limit` `--render` `--render-qc` `validate --num-keypoints` | 非负整数 | `0` 有实义（不限制 / 不渲染），必须放行 |
| `--fps` `--duration` `--bbox-margin` | 大于 0 | `--fps 0` 等于一帧都不抽，不给静默通过 |
| `--start` | 大于等于 0 | 从第 0 秒开始是最常见写法，不能被「必须大于 0」挡掉 |
| `--jpeg-quality` | 1~100 | |
| `--port` | 1~65535 | |

- **导入源路径逐个检查**：`import` / `auto` 先展开 `~` 与相对路径再判存在。打错的路径逐条打印 `[warn] 路径不存在，跳过: ...`；**全部**都不存在时直接失败（退出码 1），并提示「相对路径请写成绝对路径或先 cd 到上级目录」，不再显示「导入成功 0 张」。
- **0 张不建批次**：源都存在但一张都没入库（全是重复 / 没有支持的扩展名）时，`import` 打印「扫描 N 张，没有新图入库」并给出重复与失败计数，**不在批次表里留一个 0 张的空批次**；`auto` 把批次标为 `failed` 并终止后续标注 / QC / 坐标导出，避免产出一堆空文件看着像成功。已入库的图要重标用 `label --force`。
- **状态名与多值参数**：`reset --status` 与 `export` / `coords` / `auto` 的 `--keep-status` 只认 `unreviewed` / `edited` / `approved` / `rejected`，拼错当场报「不认识的状态「aprovied」」——以前拼错等于没写，用户以为多留了一批，其实范围一个字没变。可重复的参数（`--delete` / `--delete-images` / `pool --add` / `--classes` / `--fields` / `--keep-status`）也都接受一次逗号写完：`--delete-images a.jpg,b.jpg`。
- **`--formats` 只认 `csv` / `long` / `jsonl`**：写 `--formats xml` 以前会「导出成功」但一个文件都不生成，现在直接报「未知坐标格式: xml（可选 csv、long、jsonl）」，与网页端 `/api/coords` 的口径对齐。
- **报错只有一行**：路径打错、批次 ID 不存在、参数越界这类用户自己就能改对的问题，统一收口成一行 `[error] 中文说明` + 退出码 1，不再甩 8 行 Python 栈。怀疑是软件本身的问题时，前面加 `AUTOLABEL_TRACEBACK=1` 照常贴出完整栈。

## 多模态大模型配置

配置文件 `configs/vlm.json`（可用环境变量 `AUTOLABEL_VLM_CONFIG` 指向别处），字段如下：

| 字段 | 说明 |
| --- | --- |
| `name` | 配置名，界面与 `models` 列表按它显示 |
| `provider` | 预设：`ollama` `lmstudio` `vllm` `openai` `dashscope` `custom` |
| `kind` | `local`（本地服务）/ `cloud`（云端 API） |
| `base_url` | OpenAI 兼容地址，缺协议头会自动补 `http://`，结尾 `/` 会被去掉 |
| `model` | 模型名，如 `qwen2.5vl:7b`、`gpt-4o-mini` |
| `api_key` | 只在写入时接收明文，实际落进 `~/.autolabel/secrets.json`（`AUTOLABEL_SECRETS` 可改），配置里只留 `key_ref: vlm:<配置ID>`；读取一律掩码（`sk-…1234`），传回掩码或留空表示不修改 |
| `timeout` | 单次请求超时秒数，1–300，默认 60（连通性测试按该值等待；实际标注至少等 60 秒） |
| `max_tokens` | 回复上限 token，64–32768，默认 4096。思考型模型会把额度花在推理上，太小会回空正文 |
| `image_limit` | 送图最长边像素，256–4096，默认 1024。调小省 token 与时间，细节多的画面调大 |
| `json_mode` | 打开后请求带 `response_format: json_object`，端点支持时能少一大类解析失败，默认关 |
| `remark` | 备注说明，与「模型目录」里那条备注是同一份数据 |
| `last_test` | 最近一次连通性结果（`ok` / `message` / `latency_ms` / `checked_at`） |

```bash
python3 -m autolabel models                        # 权重 + 多模态配置一览（含备注、最后使用）
python3 -m autolabel models --browse                      # 可下载目录：中文说明、参数、体积、下载命令
python3 -m autolabel models --info yolo11m-pose           # 单个模型详情 + 下载地址 + SHA256 + 下载记录
python3 -m autolabel models --dataset datasets/demo       # 顺带判「这个模型能不能用在当前数据集」
python3 -m autolabel models --download-weight yolo11l-pose.pt
python3 -m autolabel models --note yolo11l-pose=只在内网机器下    # 写备注，等号后留空即清空
python3 -m autolabel models --default yolo11m-pose               # 设为姿态类的默认模型
python3 -m autolabel models --register ~/weights/gym.pt --display-name 体操自研
python3 -m autolabel models --forget gym                         # 取消登记，文件留原地
python3 -m autolabel models --delete-weight yolo11m-pose.pt --yes
python3 -m autolabel models --add-vlm '{"name":"本地 Ollama","provider":"ollama","model":"qwen2.5vl:7b","max_tokens":2048}'
python3 -m autolabel models --test-vlm vlm_a13bdd38        # 连通性验证，失败会说明原因
python3 -m autolabel models --default-vlm vlm_a13bdd38     # 设为默认
```

连通性验证先取 `GET {base_url}/models`（便宜，能列出模型就算通过），拿不到结果再退化成一次 `max_tokens=1` 的 `POST /chat/completions` 探测。返回文案带下一步动作，例如「连不上 http://localhost:11434/v1：本地服务没启动？Ollama 先跑 `ollama serve`」。

## 用多模态大模型标注

配置好之后，多模态大模型可以**直接当标注后端**，替换 YOLO-pose：

```bash
# 界面：导入素材的模型下拉框分成两组，选「多模态大模型」里的那条配置即可
# 命令行：--vlm 取配置 ID 或名称（label 与 auto 都支持）
python3 -m autolabel label datasets/demo --vlm 本地\ Ollama
python3 -m autolabel auto datasets/demo 视频.mp4 --vlm vlm_a13bdd38
```

- 提示词固定 COCO-17 顺序，要求只回 JSON：`{"people":[{"bbox":[x1,y1,x2,y2],"keypoints":[[x,y,v]×17]}]}`，坐标按 0-1000 整数回报（模型直接回 0-1 小数也认）。
- 解析容错：带 ```` ```json ```` 包裹、缺尾花括号、漏逗号的回复都能抢救（按 `keypoints` 数组逐个提取）；点数不足 17 补成 `v=0`，全零点当成未标注点，bbox 再按可见点撑开。
- 每条标签打 `vlm_labeled` 标记，QC 权重 1.5，整批进人工复核清单；索引里 `labeled_by` 记成 `vlm:<配置ID>`，与 YOLO 标注区分。
- 换了 `--vlm` 等于换了参数指纹，之前 YOLO 标的图会被判定需要重标（`approved` 的不动）。
- 单张要一次网络请求：本地 8B 级视觉模型实测 25–40 秒/张，比 YOLO（约 30 张/秒）慢两个数量级，建议先 `--limit 20` 试跑再放开。
- 思考型模型（返回里带 `reasoning_content`）容易把输出额度花在推理上，正文为空时会回落到思考内容继续解析；仍为空就按失败处理并写明原因。
- 单张推理失败不中断整批：计入 `failed` 并打印 `[warn] 推理失败 <图片>: <原因>`。

### `autolabel service`

```
usage: autolabel service [-h] [--status] [--restart [名字]] [--remove [名字]]
                         [--dry-run] [--show 名字] [--print-env 名字]

options:
  -h, --help      show this help message and exit
  --status        谁在跑、端口、退出原因、日志尾几行
  --restart [名字]  改完代码重启（不给名字就全部重启）
  --remove [名字]   注销并删掉生成的任务定义与启动片
  --dry-run       只把任务定义写出来，不碰服务管理器
  --show 名字       打印这个实例的任务定义（排查用，不改任何东西）
  --print-env 名字  打印这个实例的参数（服务启动片自己用）
```

实例清单 `configs/后台实例.conf` 一行一个：`名字 端口 数据集 设备 半精度`（清单不入库，仓库里给的是模板 `configs/后台实例.conf.example`，拷一份改掉端口和数据集那行即可）（设备写 `-` 表示跟「系统设置」里那档走，名字只能用字母数字和 `-` `_`，它要写进服务标签）。清单里删掉一行，下次注册自动把对应任务注销，不留僵尸反复重启。

系统差异全压在两个后端类里：macOS 写 `~/Library/LaunchAgents/com.windinchen.autolabel.<名字>.plist`（`KeepAlive = {SuccessfulExit: false}`），Windows 用 `Register-ScheduledTask` 建登录触发（`-AtLogOn`）任务 `AutoLabel-<名字>`（`-RestartCount 999` + `-RestartInterval 1 分钟` + `IgnoreNew`，对应同一个语义）。两边都指向 `~/.autolabel/services/<名字>` 下的纯 ASCII 启动片——服务管理器把中文路径传成乱码是共同的老毛病。日志在 `~/.autolabel/logs/`。

### `autolabel service-run`

```
usage: autolabel service-run [-h] [--port PORT] [--dataset DATASET]
                             [--device {auto,cuda,mps,cpu,0,1}] [--half]
                             [--wait WAIT]
                             [name]

positional arguments:
  name                  清单里的实例名；不填就用手上的参数临时起一个

options:
  -h, --help            show this help message and exit
  --port PORT
  --dataset DATASET     不读清单时临时指定数据集
  --device {auto,cuda,mps,cpu,0,1}
                        不读清单时临时指定算力
  --half                半精度推理
  --wait WAIT           最多等多少秒端口就绪
```

被服务管理器拉起的那一个：参数现读清单（改完清单 `--restart` 就生效，不用重新注册），不开浏览器，并且**端口被占时退出码是 0**——launchd 与任务计划程序都只对非零退出做「失败重启」，非零就等于让它每 10 秒撞一次你自己的工作台。它还会把真正在监听的进程 PID 写进 `~/.autolabel/services/<名字>.pid`：`uv run` 会再 fork 一个 python，服务管理器记的那个 PID 并不是在听端口的那个，状态页全靠这条 PID 才敢报「在跑」。
