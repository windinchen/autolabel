# 目标检测标注

本机的 YOLO 权重按**它自带的类别表**出框，人工只在浏览器里删错框、补漏框，导出直接喂 `yolo detect train`。

> 名字说明：这个**标注模块**从 1.4.10 起叫「目标检测标注」（顶栏、批次、命令面板统一这么写）。
> 1.4.10 曾把出框那颗按钮收成「批量检测」，结果三个标注页的批量入口三个名字、谁也不知道点了会标哪个库，
> 1.4.11 起写全：**批量目标检测标注**，与「批量姿态标注」「批量提示词标注」同一句式。**数据库仍然叫「目标检测库」**（`--lib detect`、`detect_labels/`），
> **YOLO 的任务类型仍然叫「目标检测」**（对应 `detect` / 实例分割 / 旋转框 / 分类），这两处没改也不需要改。

和「提示词标注」的区别只有一句话，但决定了该用哪个：

| | 提示词标注 | 目标检测标注 |
| --- | --- | --- |
| 谁出框 | 多模态大模型按**你写的描述**在画面里找 | 本机 YOLO 权重按**它自带的类别表**出框 |
| 类别从哪来 | 你自己定义字段（任意物品） | 权重决定（COCO-80 / 你自训练的 N 类），开放词表权重则由你填英文词 |
| 联网 | 云端配置要联网，每张一次请求 | 不联网 |
| 速度 | 秒级一张 | 几十毫秒一张 |
| 擅长 | 权重没见过的新物品、语义模糊的目标 | 常见物品、大批量预标注 |
| 界面提示语 | 「多模态大模型按你写的字段找物品」 | 「本机 YOLO 权重按自带类别出框」 |

一句话选择：**权重认识的东西用目标检测（快），权重不认识的东西用提示词标注（灵活）**。两个库共用 `images/` 素材池，同一帧只落盘一次，可以在两个模块间来回标同一批图。

## 三个标注库的分工

| | 姿态标注 | 提示词标注 | 目标检测标注 |
| --- | --- | --- | --- |
| 库名（`--lib`） | `pose` | `objects` | `detect` |
| 目标 | 人体 + COCO-17 关键点 | 任意物品（你自定义字段） | 权重自带的类别 |
| 后端 | YOLO-pose 权重 | 多模态大模型（本地或云端） | YOLO 检测 / 分割 / 旋转框权重 |
| 标签目录 | `labels/` | `prompt_labels/` | `detect_labels/` |
| 索引 | `.autolabel/index.json` | `.autolabel/objects/index.json` | `.autolabel/detect/index.json` |
| 批次表 | `.autolabel/batches.json` | `.autolabel/objects/batches.json` | `.autolabel/detect/batches.json` |
| 原件 / 撤销 | `originals/`、`history/` | `objects/originals/`、`objects/history/` | `detect/originals/`、`detect/history/` |
| 类别登记表 | —（按关键点，无类别表） | `.autolabel/fields.json` | `.autolabel/detect/classes.json` |
| 记住的选择 | 数据集 `settings` | 签名进索引 | `.autolabel/detect/prefs.json`（上次用的权重 / 类别 / 阈值） |
| 任务类型 | `image` / `video` | `prompt` / `prompt_upload` | `detect` / `detect_upload` |
| 导出 | `yolo pose train` | `yolo detect train`（`exports/*-detect/`） | `yolo detect train`（`exports/*-yolo-detect/`） |
| 复核页 | `/pose` | `/objects` | `/detect` |
| 类别上限 | — | 80 个字段 | 200 个类别 |

三库各自一套索引、批次、标签目录、原件与撤销快照，删图 / 复核 / 撤销互不影响；只有素材池共用。**独立素材库**就是这个意思：`/detect` 有自己的上传口（快捷键 `W`），也能从素材池「认领」别处已经入库的帧，不需要先跑到姿态标注页去上传。

## 界面：`/detect`

一套壳第五个页面（快捷键 `O` 在提示词标注与目标检测标注之间来回跳）。和提示词标注页唯一的差别是**先选权重、再勾权重认识的类别**：

1. **导入素材**（`W`）——图片 / 目录 / 视频，走本库自己的上传链路，入库后可以直接跑标注。
2. **类别管理**（`1`）——三步：
   - 选权重：下拉框只列**能用在本库**的权重（`models/` 里的检测 / 分割 / 旋转框），姿态权重会被列在下方并写明「这是「人体姿态」权重，检测库用不了；人体骨骼请回姿态标注」。
   - 看它认得出什么：列出该权重自带的类别表（英文名 + 中文名 + 类别号 + 类别表规模，如 COCO-80），支持搜索 / 全选 / 反选 / 清空。
     选到**开放词表权重**（`yolov8x-world.pt`、`yoloe-26x-seg.pt`）时这一步会变样：没有可勾的自带类别表，
     换成一个词输入框，你写这次要找的英文词，下面实时标出哪些是新增、哪些已在表里（见「开放词表权重」一节）。
   - 导入所选 / 加入类别表：勾中的类别进入**本库类别登记表**，同名类别永不换号。
3. **批量目标检测标注**（`G`）——按勾选的类别逐张出框，进度条上写明用的哪个权重、多少个类别、共多少张。默认**跳过**三种图：同参数已经标过的、人工点过「接受」的、人工手工画过框的；要重标勾「覆盖已有框」。
4. **复核**——删错框、拖框补漏、改类别、接受 / 驳回，`F` 跳下一张待复核。第一次改某张图的框会先备份原件，`⌘Z` / 「撤销」能退回。
5. **导出**——`⋯` 菜单里：检测框坐标 CSV / JSONL（链接带 `lib=detect`）、YOLO 训练集（分割权重出的框带轮廓时按 segment 口径写，纯方框仍是 detection）。

顶栏常驻说明条写清本库是「本机 YOLO 权重按自带类别出框」，并给出「要标权重不认识的东西去提示词标注」的入口——两页长得太像，不讲清楚一定会走错门。

## 质量标记

和提示词库共用一套标记口径，只有「来源」相关的两条按本机权重改了名，另外多一条 `masked`：

| 标记 | 含义 |
| --- | --- |
| `no_classes` | 还没有类别：先在「目标检测标注」页从模型类别表里勾选要标的类别 |
| `none_found` | 这张一个框都没有：可能确实没有，也可能模型没认出来 |
| `small_box` | 框太小（短边不足 12 像素），训练时容易学不动 |
| `edge_box` | 框贴画面边缘，目标可能被裁断 |
| `dup_box` | 同类别两个高度重叠的框，重复标注 |
| `unknown_class` | 标签里有登记表里不存在的类别号（类别被删过或手工改过盘） |
| `model_stale` | 标注用的权重/类别/阈值与当前设置不一致，建议重新标注（提示词库同一条叫 `prompt_stale`） |
| `model_failed` | 这次推理失败（权重缺失/显存不足/读图失败），框是旧的或缺失（提示词库同一条叫 `vlm_failed`） |
| `masked` | 这一框出自**分割权重**，轮廓已随框落盘（正向标记，不算缺陷、不催复核） |
| `manual` | 人工补画或重画的框（不是模型给的），导出时置信度按 1 计 |

复核优先级由这些标记加权得出，`small_box`/`dup_box`/`model_failed` 排在前面。导出的
坐标 CSV/JSONL 与 `meta.json` 的列说明也按本库口径写（讲的是 `detect_*`，不会拿
`prompt_stale`/`vlm_failed` 教人）。

## 开放词表权重：类别你自己填（YOLOE / YOLO-World）

上面那条「类别由权重自带的类别表决定」有一条例外：**开放词表权重**。它不查自己那张表，
而是你这一轮想标什么就填什么英文词，模型按词的含义去画面里找。

| | 普通权重（`yolo11n.pt`） | 开放词表权重（`yolov8x-world.pt`、`yoloe-26x-seg.pt`） |
| --- | --- | --- |
| 类别从哪来 | 权重自带的 COCO-80，改不了 | 你这一轮填的英文词，一次最多 80 个 |
| 想标"COCO 里没有的东西" | 只能自己训一个权重 | 直接把词填进去就行 |
| 第一次用 | 只下权重 | 还要一份约 338 MB 的文本编码器权重（自动下） |
| 换一批类别 | 换权重 | 改词表，权重不用重载 |
| 界面 | 勾选权重自带的类别 | 输入框里写英文词 |

用法只有三步：

1. 「模型管理」里搜 **开放词表** / `world` / `yoloe`，下载一档（YOLO-World 只有 v8 一代，
   YOLOE 有 11 / 26 两代）；
2. 到 `/detect` 的「类别管理」选中这个权重——面板会自动换成词输入框，写几个英文词，点「加入类别表」；
3. 「批量目标检测标注」照常开跑。词表会跟着参数指纹记进索引，**换词表等于换参数，会重标**。

几条必须知道的：

- **只能填英文**。这不是格式洁癖：文本编码器是英文词表，填中文**不报错也不警告，只是一个框都找不到**
  （本机实测 `["人","狗","猫"]` 零检出）。所以词表这一步直接挡住中文，中文显示名照样可以写。
- **词要短**。`traffic cone`、`safety helmet` 这种没问题；`a person wearing a red helmet and jeans`
  这种长句子会明显掉点，所以单个词限 48 字符。
- **类别号规则不变**。填进去的词还是走本库类别登记表，同名永不换号，换权重也不改号；
  先前标好的框不会因为换词表指到别的东西上。
- **分割档连轮廓一起落**（v1.4.6 起）。`yoloe-*-seg.pt` 这类分割权重除了方框还会落
  多边形轮廓，导出能直接出 `task: segment` 的分割训练集；开放词表本身不改这件事
  （普通的 `yolov8n-seg.pt` 一样出轮廓）。
- 换普通权重时那句「这个模型认不出这些类别」在这里不会出现：词是你填的，不存在认不出，
  只有词填得不合规矩（中文 / 超长 / 超 80 个）会当场报错。

命令行同一套：

```bash
# 看这个开放词表权重该怎么用（普通权重是列出自带类别表）
python3 -m autolabel detect <数据集> --model-classes yolov8x-world.pt

# 把要找的英文词登记成本库类别，并直接开跑
python3 -m autolabel detect <数据集> --model yolov8x-world.pt \
    --add-classes "person,dog,traffic cone,safety helmet" --conf 0.25
```

依赖状况在「系统设置」里能看到一行的（`autolabel settings` 命令行同样打印）：
缺依赖不是故障，第一次用开放词表权重时会自动装好，之后离线可用。

## 类别号：谁说了算

**由本库登记表决定，不是模型说了算。** COCO 里 `bus=5`，但你的登记表可能给 `bus=0`；标签文件里写的是**登记表的号**。

- **同名类别永不换号**：换权重（COCO-80 → 自训练 3 类）时同名的 `person` 继续用同一个号，先前标好的框不会一夜之间指错东西。
- **删掉的号不回收**：删了 `bus`（原 0 号）之后新建的类别拿新号，不会顶回 0 号——否则历史标签里残留的 0 号会被重新解释成别的东西。
- **开放词表权重反过来**：它没有"自带类别表"可对照，登记的词**就是**这一轮要找的东西，
  所以不存在「权重认不出」这回事；这条路上唯一的失败是词不合规矩（中文 / 超 48 字符 / 超 80 个），当场报错。
- **只登记这个权重真的报得出的类别**（普通权重）：`--add-classes gas stove` 这种权重不认识的名字会被列进 `not_in_model` 并**拒绝登记**，因为收进来一个模型认不出的类别，下次「按本库全部类别标注」会整批报「认不出这些类别」，等于自己埋雷。想手工登记别的名字走「类别管理 → 新建」或 `autolabel fields --lib detect`。
- **允许词间空格**：COCO 的 `potted plant`、`fire hydrant`、`dining table` 是模型原样回报的写法，本库照收（提示词库仍然不允许，那里的类名是多模态大模型必须原样回报的 JSON 值）。导出 `data.yaml` 时会自动加引号。
- **上限 200 个类别**，一次批量最多勾 200 个。

## 模型管理：搜到 → 看懂 → 下载 → 用

`/models`（快捷键 `M`）现在按**任务**组织：`全部 / 姿态估计 / 目标检测 / 实例分割 / 旋转框检测 / 图像分类`。

- **搜索框**输入即搜（400ms 合并请求），本机模型目录按名字、任务、说明匹配，直接给中文介绍：体积 / 参数量 / 精度 mAP / 速度档位 / 适合场景 / **能标哪些类别**（COCO-80、COCO-17、ImageNet-1000）。
- **开放词表那几档一眼能认出来**：搜「开放词表」「world」「yoloe」都能找到，它们的「能标哪些类别」
  写的不是 COCO-80 而是「类别不固定，标注时自己填英文词」，点进去文档页也直接指向
  YOLO-World / YOLOE 各自的模型页。精度那一列留空——官方给的是 LVIS 上的数字，
  和这张表里 COCO-80 的 mAP 不是同一把尺子，并排放会让人误判谁强谁弱。
- **「联网搜 GitHub」** 默认关；开了才会去 GitHub 检索仓库级结果，慢。网络不通**不报错**，只在搜索框下面写「联网检索不可用：{原因}」，本机目录照常显示。GitHub 结果只有「打开 GitHub」和「复制仓库名」——那是仓库不是权重，没有可直接下载的地址，别指望一键下载。
- **下载**沿用原来的权重下载链路（带进度条、断掉的 `.part` 能看见能删）。
- **默认模型只有一个入口**：目录卡片上没有「设为默认」了，去下面的**模型列表**——那一行按权重的任务给出「设为目标检测标注默认」（写的是**这个数据集的目标检测库下次用哪个权重**，存 `.autolabel/detect/prefs.json`）或「设为姿态标注默认」（写的是**这台机器**的姿态默认权重，存 `configs/models.json`）。两份默认仍然存在两个地方，只是不再有两个入口。
- **「更新目录」** 联网核对官方最新发布，新档位连中文介绍一起补进目录、体积跟着改正，缓存进 `configs/models.json` 的 `hub_catalog`；断网只说一句原因，目录保持原样。本模块可用的新档位一进来，检测页的权重下拉框（只列已下载 + 本模块能用）就能选到。

命令行：

```bash
python3 -m autolabel models --search yolo11 --task detect        # 搜本机模型目录，带中文介绍
python3 -m autolabel models --search yolo --task detect --remote  # 顺带联网搜 GitHub
python3 -m autolabel models --browse                              # 完整可下载目录
```

## 命令行

```bash
D=datasets/goods
python3 -m autolabel init    $D --name 货物
python3 -m autolabel import  $D ~/Pictures/货架 --lib detect        # 素材直接进目标检测库
python3 -m autolabel detect  $D --list-models                       # 本机哪些权重能用在本库
python3 -m autolabel detect  $D --model-classes yolo11n.pt          # 这个权重认得出哪些类别
python3 -m autolabel detect  $D --model yolo11n.pt --add-classes bus,person
python3 -m autolabel detect  $D --model yolo11n.pt --add-classes all --no-label   # 全部 80 类只登记不标注
python3 -m autolabel detect  $D --classes bus,person --coords --batch-name 上午批次
python3 -m autolabel detect  $D --status                            # 已标 / 待复核 / 按类别统计
python3 -m autolabel detect  $D --probe "t-shirt,shirt" --model yolov8x-worldv2.pt  # 试词：只读，不改数据
python3 -m autolabel detect  $D --export --out exports/goods        # YOLO 训练集（带轮廓自动按 segment 写）
```

`--add-classes bus,person` 之后直接就跑标注了；只想登记类别不想跑推理加 `--no-label`。没选权重时的顺序：**显式 `--model` → 本库上次用的（prefs）→ `yolo11n.pt`**。

一条命令跑完（导入 → 标注 → 坐标）：

```bash
python3 -m autolabel auto $D ~/Pictures/货架 --lib detect --model yolo11n.pt
```

### 参数

| 参数 | 作用 |
| --- | --- |
| `--model 权重` | 权重文件名或路径，默认上次用的那个，它决定能标哪些类别 |
| `--list-models` | 列本机权重，标出哪些能用在本库（姿态权重说明为什么用不了） |
| `--model-classes 权重` | 列这个权重自带的类别表（中文名 + 类别号），只看不动数据 |
| `--add-classes 类名` | 把权重自带的类别导入本库登记表，逗号分隔可重复，`all` 全部导入 |
| `--no-label` | 配合 `--add-classes`：只登记类别，不跑标注 |
| `--classes 类名` | 只标这些类别，默认用本库登记表里全部 |
| `--images 相对路径` | 只标这些图，默认整个目标检测库 |
| `--device` | `auto\|cuda\|mps\|cpu`，`0`/`1` 指定第几块 N 卡；默认用系统设置那档 |
| `--conf` | 置信度阈值，默认用系统设置里的值 |
| `--imgsz` | 输入分辨率，默认用系统设置里那档；服装 / 小物件提到 1024 明显更容易出框 |
| `--limit` | 只标前 N 张，试跑用 |
| `--overwrite` | 已标过的也重标（默认跳过同参数已标、人工接受、人工画过框的） |
| `--coords` / `--export` / `--out` | 顺带导出坐标文件 / YOLO 训练集 / 指定导出目录 |
| `--batch-name` | 批次名称，用于「批次管理」分组 |
| `--status` / `--quiet` | 只看汇总 / 不逐张打印 |

## 产物

```
datasets/<名称>/
├── detect_labels/<同名>.txt            YOLO detection 5 列；带轮廓时后面接归一化点列
├── coords/<时间戳>-detect/             objects.csv、objects.jsonl、meta.json、summary.json
├── exports/<时间戳>-yolo-detect/       images/ labels/ data.yaml（task 是 detect 或 segment） yolo_meta.json
└── .autolabel/detect/
    ├── index.json                      本库索引（detect_* 状态）
    ├── batches.json                    本库批次登记
    ├── classes.json                    类别登记表：类名 → 永不复用的类别号
    ├── prefs.json                      上次用的权重 / 类别 / 阈值
    ├── originals/                      首次人工修改前的原件备份
    └── history/                        撤销用的历史快照
```

索引字段一律带 `detect_` 前缀（`detect_objects` / `detect_status` / `detect_flags` / `detect_signature` / `detect_score` / `detect_classes` / `detect_model` / `detect_manual`），和姿态库、提示词库的字段互不覆盖。

## 接口

同一件事只有一个入口：检测框的读写仍走 `/api/prompt/*`，靠 `lib` 参数分流（缺省 `objects`）；只有真正新增的能力才开新接口。

| 接口 | 说明 |
| --- | --- |
| `GET /api/detect/models` | 本库能用的权重、不能用的连同原因、上次选择（prefs） |
| `GET /api/detect/model/classes?model=` | 这个权重自带哪些类别（含中文名） |
| `POST /api/detect/classes/add` | 把权重自带的类别导入本库登记表 |
| `POST /api/detect/prefs` | 设为本库默认权重（只认可用在检测的权重） |
| `POST /api/detect/run` / `/api/detect/upload` | 批量标注 / 上传并标注 |
| `GET /api/detect/summary` | 本库总览 |
| `GET /api/modelhub/search?q=&task=&remote=1` | 模型管理页的搜索（本机目录 + 可选联网） |
| `GET/POST /api/fields`、`/api/prompt/item`、`/api/prompt/status`、`/api/prompt/undo`、`/api/prompt/export`、`/api/prompt/coords` | 与提示词库共用，带 `lib=detect` 即作用于本库 |

## 常见问题

**下拉框里没有我刚放的权重**——权重目录由 `AUTOLABEL_WEIGHTS_DIR` 或默认 `models/` 决定；`--list-models` 会列出目录里的全部并说明哪些为什么不能用。改名成 `-seg` / `-obb` 结尾会被识别成分割 / 旋转框权重。

**跑起来报「这是「人体姿态」权重」**——`yolo11n-pose.pt` 之类的姿态权重出的是关键点不是框，回 `/pose` 用它。

**换了权重之后类别对不上**——不是 bug：`person` 在两个权重里都存在就继续能标，只有新权重不认识的类别会落空，任务完成消息会写明「该权重认不出 xxx」。去类别管理里按新权重重新勾一遍即可。

**跑完显示「标注 0 张」**——这些图同参数已经标过、或者被人工接受 / 手工画过框保护起来了。要重标勾「覆盖已有框」或加 `--overwrite`。

**框一个都没有，但东西明明在画面里**——八成不是没检出来，而是**分数没到阈值**。现在跑完会直接告诉你差多少：

```
[hint] 这些类别差一点就过阈值：shirt 0.026 · t-shirt 0.020（当前阈值 0.25）
       ——把置信度降到 0.025，或把输入分辨率提到 1024 再跑一次
```

本机实测同一张白 T 恤棚拍照（`yolov8x-worldv2.pt`）：`person` 0.965、`man` 0.578，
而 `shirt` 0.026、`t-shirt` 0.020、`jeans` 0.021——**服装这一族在开放词表上天生分低**
（它的图文对齐来自 LVIS，「穿在身上的衣服」不算一个目标）。两条出路：

- **降置信度**：批量运行面板那个框可以低到 0.01，实测这张图 0.02 就出框。
- **提分辨率**：`⌥S` 系统设置 → 输入分辨率 → 1024，同一张图同一个词从 0.026 变 **0.553**。

被阈值挡掉的候选只用来解释「为什么没框」，**不落盘**、不进类别统计、不影响复核；
一次最多报 6 个，按分数排，已经在别的图上出过框的类别不会混进来。
另外词本身也影响分数：`white t-shirt`、`person wearing a t-shirt` 这种长短语比 `shirt` 更差。

**首次打开检测页有点慢**——开页会在后台取一次上次权重的自带类别表（首次加载权重 1–3 秒），这样点开「类别管理」时列表不是空的。

**导出里没有某个类别**——那个类别在当前数据里一个框都没有，`data.yaml` 只写实际用到的类别。

**分割权重的轮廓存在哪**——就存在同一张标签里，接在 5 列方框后面：
`class cx cy w h x1 y1 x2 y2 ...`（点坐标同样归一化）。**前 5 列一个字符都没变**，
只认方框的老逻辑（框数、类别占用、复核签名）统统照旧；`autolabel validate` 认得这串尾列，
点数不成对、少于 3 个点、坐标越界才会报，不再把轮廓当成「多写的列」。

**导出会跟着切成 segment 口径**——标签里有轮廓时，带轮廓的框写成 YOLO 标准分割行
（`class x1 y1 ...`），只有方框的框仍写 5 列，`data.yaml` 标 `task: segment`
（YOLO 的分割训练两种行都吃）；一个轮廓都没有时输出与老版本完全一致，`task: detect`。
导出完成的提示里会写明「多少个框带轮廓、多少个只有方框」。本机实测
`yolov8n-seg.pt` 跑 `bus.jpg`：5 个框各带 7–16 个点，导出后 `data.yaml` 是
`task: segment`，训练命令不用改一个参数。

**某些框只有方框没有轮廓**——两种正常情况：这一轮出自普通检测权重（压根没有 mask）；
或者 mask 解析不出来、解析出来的轮廓与方框对不上（IoU 低于 0.25 直接丢弃）。
后者是故意的：与其写一个套错位置的形状骗过训练，不如只留方框。想知道哪些框有轮廓，
看坐标 CSV 的 `poly_points` 列（0 = 只有方框）。

**轮廓现在能手工拖点了**（v1.4.8 起）——选中一个带轮廓的框，轮廓上会浮出**实心圆点**
（顶点）和**空心小圆**（边中点）：拖实心点改形状，拖空心点在那条边上加一个点，
`Alt + 点` 删掉一个点（最少留 3 个）。松手后方框自动收成轮廓的新外接框（那条虚线跟着走），
不会出现"框是框、形状是形状"的对不上。拖动 / 缩放方框时轮廓照旧按新老方框仿射跟随。
人工新画的方框仍然不带轮廓——那是你画的框，硬套一个轮廓是编数据；要给一个纯方框补出形状，
只能对它重跑一次分割标注。轮廓点数上限 200，坐标一律夹回画面内。

**旋转框（`-obb`）也一样**——斜的目标按外接水平框记录，旋转角不落盘。

**开放词表权重跑完一个框都没有**——先看词表是不是填了中文。文本编码器只认英文，
中文词**不报错、不警告，只是零检出**（本机实测），所以本库在登记这一步就把中文挡住了；
万一词表是从别处导入的老中文名，跑之前也会当场报错而不是白跑一轮。

**怎么确认我写的词这个权重到底认不认识**——用**试词**：目标检测标注页「类别管理」里的
「先试词」按钮（或 `⌘K` 搜「试词」），命令行是 `autolabel detect <数据集> --probe "t-shirt,shirt,top"`。
它拿当前这张图跑一次、**只读不写**，一个词一行回你：最高分、过没过阈值、以及下一步该改什么。
「一个框都没有」其实是三种病，试词把它们分开报：

| 试词报的内容 | 真实原因 | 下一步 |
| --- | --- | --- |
| `这个权重没有这一类` | 普通权重的类别表是固定的（COCO-80 里没有 `t-shirt`） | 换开放词表权重（`yolov8x-worldv2.pt` / `yoloe-26x-seg.pt`），词由你填 |
| `检得出但被阈值挡住` | 词是对的，分数低于阈值被丢掉（实测 `shirt` 在 640 只有 0.026 分） | 按它算好的数字降阈值，并把输入分辨率提**一档**（640 → 1024 实测 `shirt` 涨到 0.553；已经在 1024 就提 1280，到顶会直说没有更高一档） |
| `这张图上一点分都没给` | 图里确实没有，或这个词模型压根没对齐 | 换图确认；再把词换成更常见的英文写法（`shirt` 而不是 `white t-shirt`） |

界面上试完直接给两个按钮：「把这些词导入类别表」和「按建议阈值去标注」，不用回头手动填数。
一次最多试 12 个词；开放词表第一次试要下文本编码器权重（约 338 MB），之后就快了。

**开放词表第一次用特别慢**——正常。第一次要装文本编码器的依赖并下载约 338 MB 的编码器权重
（本机实测整批约 30 秒，其中下载占大头），之后换词表只要 1–12 秒，权重本身不再重新加载。
「系统设置」里有一行写着这件事，`autolabel settings` 也打印。

**开放词表怎么只让填 80 个词**——每个词都要过一次文本编码器，几百个词纯粹拖时间；
真需要两百个类别，通常是该考虑自己训一个权重，而不是把两百个词塞进一次推理。
