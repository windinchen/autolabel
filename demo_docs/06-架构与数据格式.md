# 架构与数据格式

## 模块划分（`autolabel/`）

| 文件 | 职责 |
| --- | --- |
| `cli.py` | 命令行入口与参数（`label` 与 `auto` 共用一套标注参数）、`--lib` 选库、`pool`/`migrate` 子命令；数值参数带范围校验（比例 0~1、尺寸/帧数正整数、端口 1~65535），状态参数 `_review_statuses()` / `_status_words()` 只认四个真实状态（拼错当场报错，不再等于没写），可重复参数一律过 `_split_multi()` 兼容逗号写法，`validate` 三个库都查并比对索引框数（`missing_file` / `count_mismatch`），导入源先判存在、0 张入库不建批次，`main()` 把 `FileNotFoundError`/`ValueError`/`KeyError` 收口成一行 `[error]`（`AUTOLABEL_TRACEBACK=1` 贴栈） |
| `backends.py` | 推理后端：YOLO-pose（翻转融合 TTA、多模型共识、可见性判定——先定 `v` 再按参与监督的关键点定 bbox）与 `DetectionBackend`（检测 / 分割 / 旋转框三种任务出框，`DETECT_TASKS` 是这三种，姿态权重喂进来直接报中文错误）；权重下载与设备选择（CUDA / MPS / CPU / 指定卡号，不可用时降级并说明）；`default_weights_dir()` 让推理侧与模型管理页认同一个 `AUTOLABEL_WEIGHTS_DIR`，`claim_download()` 用文件锁保证同一个 `.pt.part` 只有一个下载者，`partial_paths()` 报出半截的 `.part` / `.bad` |
| `models.py` | 模型管理：统一模型清单（内置目录 + 本地登记 + **按磁盘文件补的权重行**）与兼容性判定、默认值/本地登记（`configs/models.json`）、权重清单与后台下载（含下载记录）、多模态配置（`configs/vlm.json`）与连通性验证 |
| `modelhub.py` | 模型管理页搜索框的数据层：在 `models.PRESET_CATALOG` 之外补齐检测 / 分割 / 旋转框 / 分类四种任务的目录（体积按 ultralytics/assets release 实际字节数核实、参数与精度取官方模型表，官方没给的填 `None` 并在中文说明里写明）；离线匹配 `search()` 是主路径，联网 `search_remote()` / `search_payload()` 只是加分项（断网、超时、限流一律安静降级不抛异常），每行直接带前端要渲染的别名字段（`task_label`/`intro`/`params`/`bytes`/`installed`），下载仍复用 `models.start_download()` / `backends.ensure_weights()`。中文整句也能搜到：`_slices()` 把五个字以上的中文切成二字窗口，`_informative_windows()` 丢掉命中过半数条目的碎片（否则「什么」这种词谁都命中、结果永远第一），`_hint_score_partial()` 让长句里的「快 / 精度 / 小 / 大」也计分——`能标轮廓的`、`最省显存的` 有结果，而 `旋转框` 这种精确短词不会被稀释；搜不到的还是空列表，不硬凑 |
| `secrets.py` | API Key 集中存放（`~/.autolabel/secrets.json`，0600），配置里只留 `vlm:<配置ID>` 引用名 |
| `vlm.py` | 多模态大模型标注后端：提示词、图片编码、chat 请求、残缺 JSON 解析成 `Person` |
| `batches.py` | 批次登记、按批次统计与整批/按张删除（含删除前快照，只留最近 200 份）、三库进度合并、启动对账（补回孤儿图片、中断批次收尾，带库归属优先权；每库只解析一次其它库索引，不按张重读）；`delete_images(lib="all")` 三个库的引用一起摘（素材是否删由 `mode` 决定，「图只在别的库里」不再算「查无此图」），`_snapshot_order()` 按 `(时间戳, 后缀序号)` 排快照——同一秒写的多份按写入顺序清理，认不出的文件名排最后、永不被删。删除快照不再只写不读：`list_snapshots()` 列出每份的删除时间 / 模式 / 张数 / **可装回张数**（原图已删的不算），`restore_deletion()` 把标签原文写回、索引条目装回、批次记录补回（`retired` 恢复成 `done`）并给导入批次重盖来处章，装完吃掉这份快照；一张图回哪个库先看它原来挂的批次属于哪个库，再看快照里哪个库存过它的标签原文，往「不是自己那份」的库装回时只搬素材层通用字段 |
| `library.py` | 三个标注库的读写底座与**库名/路径唯一来源**：库名归一化（`pose`/`objects`/`detect`，带 `det`/`detection` 等别名）、每库一套 `LIB_SPECS`（标签目录 / 元数据目录 / 索引字段前缀）、素材池清单与认领（`adopt_from_pool`）、跨库导入复用、旧版单索引布局拆分迁移（`migrate`）、缺失库索引补齐（`ensure_objects_index`）、类别登记表路径（提示词库 `fields.json`、目标检测库 `detect/classes.json`，结构一致） |
| `fields.py` | 类别登记表（按 `lib` 分文件：提示词库 `.autolabel/fields.json`、目标检测库 `.autolabel/detect/classes.json`）：名称/显示名校验、`class_id` 分配与**同名永不换号、删号不回收**、调色板配色、框的读写与孤儿类别号。名称校验按库分档——提示词库要求单 token（要写进 `data.yaml` 和模型提示词），目标检测库放开**词间空格**（COCO 里 `traffic light`、`potted plant` 这类名字有 15 个）；上限也不同（80 字段 / 200 类别）；`delete_field(drop_boxes=True)` 重写标签文件之后**顺手把索引里的框数落回真实值**（`_strip_class()`，否则列表页写着 3 个框、点开编辑器只剩 1 个），`box_counts_by_image()` 供 `validate` 逐张比对索引与磁盘 |
| `prompt.py` | 提示词标注：拼提示词、标注签名、模型回复解析成 `Detection`、质量标记与优先级、坐标文件导出；`export_detection_dataset(lib=…)` 与 `write_detections` / `read_detections` / `render_object_coords` 是**两个出框库共用**的底层，目标检测库传 `lib=detect` 即复用同一套产物格式 |
| `detect.py` | 目标检测标注：`task_of()` 判权重任务、可用权重清单（姿态权重连原因一起返回）、`resolve_model()` 三级兜底（显式指定 → 本库 prefs → 默认权重）、`model_profile()` 中文说明、按勾选类别批量出框与索引回写、`add_model_classes()` 只登记该权重真报得出的类别（其余进 `not_in_model`）、本库默认权重偏好（`.autolabel/detect/prefs.json`）、`module_summary()` 分库统计 |
| `classnames.py` | 常见数据集类别的中文名对照表（COCO-80 等），只这一处；表里没有的类名退回英文，绝不编一个不像的中文名 |
| `pipeline.py` | 批量标注、断点续跑（逐张比参数指纹）、人工结果保护（`approved`/`edited` 默认不进重标队列）、QC 打标、进度回调、按图合并落盘 |
| `yolo_pose.py` | 标签格式读写/校验、COCO-17 常量、镜像翻转、bbox 自愈、合理性检查 |
| `dataset.py` | 目录布局、索引 `DatasetIndex`（按库取路径）、导入与去重、EXIF 规范化、素材池命中即复用；`DEFINITIVE_STATUSES`（已定论）与 `HUMAN_STATUSES`（人工碰过，默认不进重标队列）两条状态线在这里定义一次，三条标注链路与 `qc` 共用；`source_missing()` / `missing_sources()` 是「索引里记着、`images/` 里没了」的唯一判口，导出 / 坐标 / `status` / `validate` 共用同一个口径；`IMAGE_EXTS` 是「哪些后缀算图片」的唯一口径（界面上传直接取它，不再自己写一份） |
| `pool.py` | **素材池账本**（`.autolabel/pool.json`）：分类表 + 池导入批次 + 每张素材的素材层字段。口径是**素材归池，标注归库**——分类与来处是素材层的属性只存一份，标状态仍留在各库索引；池批次 ID 带 `p_` 前缀、库批次是裸 hex，删除与对账都按前缀分流（`is_pool_batch()` / `delete_pool_batches()`）；`pool_only_rels()` 给出「只进池还没入库」的素材，启动对账靠它不把这些孤儿图抢进姿态库；`keep_tracked_in_pool()` 把「文件还在但已无库引用」的素材补记回账本（哈希、体积、尺寸、进池时间），否则同一批图再传一次认不出重复。来处章 `items[rel].batch` 由 `attach_items()` 盖、**只认第一次**（同一帧被第二个模块再导一次不改挂），`detach_batch()` 只在连原图真删时摘章；`import_records()` 给素材池页的批次记录——池批次 + 各库导入批次 + 各库标注批次合成一份，每行带 `action`（导入 / 标注）与按章点出来的张数 |
| `atomic.py` | 整文件原子落盘：临时名带进程号 + 进程内自增序号（线程号会被复用），写完 `os.replace` 换名。三个库的索引、批次表、类别登记表、两份模型配置、Key 表全走这里——以前六处同名 `x.tmp`，两个实例并行会把对方的文件截断成残缺 JSON |
| `review.py` | 复核 HTTP 服务（六个页面 + JSON API）、`ReviewStore`（写标签、备份、历史快照、撤销、按 `lib` 重读三库索引、检测框读写、素材池接口（清单 / 认领 / 分类增删 / 逐张归类）、启动对账、`save_detect_prefs()`）；标注 / 检测任务启动前先 `_refresh_if_changed()` 重读磁盘索引，避免 CLI 刚导入的图被判成「库里还没有图片」 |
| `upload.py` | 上传落盘（`save_upload_stream()` 分块读写，超限也把请求体读干净；`IMAGE_EXTS` 直接取 `dataset.IMAGE_EXTS`，界面能传的必定就是命令行能导的——以前 `.tif/.tiff` 网页拒收、命令行却能导入并转 JPEG）、`Job`/`JobStore` 后台流水线（`image` / `video` / `pose` / `prompt` / `prompt_upload` / `detect` / `detect_upload` 七类任务，任务参数里的 `lib` 决定入库到哪个库。前两类要先把素材收进库，后五类的素材早就在库里了，只是重跑标注。另有 `pool` 一类：**只进池不入库**，批次记在池账本上（`p_` 前缀），任务跑完必须同时落 `result` 与 `finished/ok`，否则素材池页的进度条会永远转、删除也会一直被「还在导入中」拦住） |
| `coords.py` | 坐标文件导出（宽表 / 长表 / JSONL / meta / summary）、按需渲染下载；`KNOWN_FORMATS` 校验格式名，未知格式抛 `ValueError` 而不是静默产出 0 个文件；`collect_records()` 跳过源文件已不存在的帧并记进 `skipped`（这些帧的坐标只能凭索引里的旧计数编出来，宁可不给） |
| `qc.py` | 统计、优先级排序、`report.md` / `stats.json` / `flags.csv`、骨架叠加图；`dataset_stats()` 单列 `missing_files` / `missing_images`（缺源文件的帧既不算「缺标签」也不算「坏标签」，不点名就没人知道图没了） |
| `export.py` | train/val 划分（按 `(seed, 相对路径)` 哈希分桶，成员稳定）、`data.yaml`（`flip_idx_for()` 按关键点数收敛）、COCO keypoint JSON（点数不足补零）、manifest；`export_stem()` 把子目录压进导出名（`a/x.jpg` → `a__x.jpg`，两条链路共用），`unique_stem()` 处理压平后与真实同名文件的撞车（加 `-2`，否则磁盘悄悄少帧），`prune_stale()` 清掉重复导出时上一版遗留、这一版已驳回的帧（记进 `counts["pruned"]`），`yaml_scalar()` / `yaml_comment()` 只给会被 YAML 误读的类名加引号（`安全帽: 大` 不加引号会让整份 `data.yaml` 解析失败），`_place()` 的软链走相对路径；`MISSING_SOURCE_REASON` 把源文件已消失的帧挡在导出集外（`copy` / `hardlink` 以前直接抛 `[Errno 2]` 中断整场导出，`symlink` 更阴——产出一根指向空气的软链还照报张数），计数记进 `counts["missing_source"]` |
| `video.py` | ffmpeg 探测与抽帧（定帧率 / 场景切点），记录时间戳；ffprobe 60 秒超时、抽帧按片段长度推导超时（`AUTOLABEL_FFMPEG_TIMEOUT` 可覆盖） |
| `thumbs.py` | 队列缩略图：长边 320 的 JPEG 缓存在 `.autolabel/thumbs/`，文件名编了 `(路径, mtime, 大小)` 指纹所以可长期缓存；坏图回退原图，启动时清理久未使用的 |
| `image_utils.py` | 读图、dHash、骨架绘制 |
| `static/` | 前端（原生 HTML/CSS/JS，无构建）：`portal.*` 工作台、`review.html` + `app.js` 姿态标注、`objects.html` + `objects.js` 提示词标注、`detect.html` + **同一个 `objects.js`** 目标检测（脚本开头一张 `LIB_CONFIG` 表决定库名/接口/文案/标签目录，分界线以下不许出现写死的库名）、`models.*` 模型管理（搜索框 + 按任务筛选）、`pool.*` **素材池**（分类条 / 素材网格 / 批次视图 / 认领与删除）、`common.js` 六页共用的导航/确认弹窗/素材池选择器/系统设置/请求工具；模块清单 `MODULES` 只有一张表，顶栏标签和 `⋯` 菜单里的「去别的模块」都按它现渲染，各页 HTML 只留一个 `#menu-modules` 占位（左侧竖条不再挂模块跳转） |

依赖方向：`cli → {backends, pipeline, dataset, review, coords, export, qc, video, upload, batches, library, models, modelhub, fields, prompt, detect}`；`review → thumbs → library`；`batches → library`（库名/路径/素材池的唯一来源）；`review → upload → {dataset, pipeline, qc, coords, batches, detect}`；`prompt → {fields, vlm, dataset, coords, export}`（类别表由 `fields.py` 单一来源提供）；`detect → {prompt, fields, backends, library, classnames}`（出框库的产物格式只在 `prompt.py` 定义一份，`detect.py` 不另起一套）；`modelhub → models`（只补目录与搜索，下载委托回 `models`）；`pipeline → backends.build_backend → vlm → models`；`models → {backends, secrets}`（权重下载委托给 `backends.ensure_weights()`，API Key 交给 `secrets.py`，删配置时连带删掉那把 Key）；所有整文件写入（索引 / 批次 / 类别表 / 两份配置 / Key 表）统一走 `atomic.atomic_write_json()`，重依赖（ultralytics、ffmpeg）全部在函数内延迟导入。

## 数据集目录

```
datasets/<名称>/
├── images/            共享素材池：规范化图片（jpg），同一帧只落盘一次，三个库都能引用
├── labels/            姿态库标签（YOLO pose，与 images 同名同层级）
├── prompt_labels/     提示词库标签（YOLO detection 5 列，与 images 同名同层级）
├── detect_labels/     目标检测库标签（YOLO detection 5 列；分割权重多一段轮廓点列）
├── qc/                report.md、stats.json、flags.csv、overlays/
├── coords/            坐标文件（每个时间戳或 upload-<jobid> 一个子目录；骨骼 / 提示词框 / 检测框三套文件）
├── exports/           训练数据集（images/labels/data.yaml/manifest.json/coco_keypoints.json）
└── .autolabel/
    ├── index.json     姿态库索引（本库事实来源，位置与老版本一致 → 老数据集零迁移）
    ├── batches.json   姿态库批次登记表
    ├── pool.json      素材池账本（分类表 + 池导入批次 + 每张素材的素材层字段）
    ├── originals/     姿态库首次人工修改前的自动标注原件
    ├── history/       姿态库每张图最近 10 个历史快照，供 U 撤销
    ├── fields.json    提示词库的字段登记表（name / label / prompt_hint / class_id / color）
    ├── objects/       提示词库（整库独立）
    │   ├── index.json     提示词库索引
    │   ├── batches.json   提示词库批次登记表
    │   ├── originals/     检测框首次修改前的模型原始标注
    │   └── history/       检测框历史快照，供撤销
    ├── detect/        目标检测库（整库独立，该库第一次用到时自动建）
    │   ├── index.json     目标检测库索引
    │   ├── batches.json   目标检测库批次登记表
    │   ├── classes.json   本库类别登记表：类名 → 永不复用的类别号
    │   ├── prefs.json     上次用的权重 / 勾选的类别 / 阈值（模型列表「设为目标检测标注默认」写这里）
    │   ├── originals/     检测框首次修改前的权重原始标注
    │   └── history/       检测框历史快照，供撤销
    ├── deleted/       删除快照（索引字段 + 各库标签原文 + 来自哪个库），误删找回依据；只保留最近 200 份
    ├── thumbs/        队列缩略图缓存（可随手删，缺了就地重新生成）
    └── uploads/       网页上传临时文件，任务成功后清理；启动时清掉上次进程遗留的（超过 24 小时未修改）
```

## 三个标注库与素材池

「姿态标注」「提示词标注」「目标检测标注」是**三个独立的库**，口径一直是 **素材池共享、标注库独立**：

| 维度 | 姿态库 `pose` | 提示词库 `objects` | 目标检测库 `detect` |
| --- | --- | --- | --- |
| 索引 | `.autolabel/index.json` | `.autolabel/objects/index.json` | `.autolabel/detect/index.json` |
| 批次表 | `.autolabel/batches.json` | `.autolabel/objects/batches.json` | `.autolabel/detect/batches.json` |
| 标签 | `labels/` | `prompt_labels/` | `detect_labels/` |
| 撤销/原件 | `originals/`、`history/` | `objects/originals/`、`objects/history/` | `detect/originals/`、`detect/history/` |
| 类别登记表 | —（按关键点，无类别表） | `.autolabel/fields.json` | `.autolabel/detect/classes.json` |
| 索引字段前缀 | 无前缀（沿用老数据集） | `prompt_*` | `detect_*` |
| 吃的任务 | pose | 多模态大模型（本地/云端） | detect / segment / obb |
| 坐标产出 | `coords/`（骨骼宽表） | `coords/`（检测框宽表） | `coords/`（检测框宽表，`-detect` 后缀） |
| 训练集导出 | `exports/*`（`yolo pose train`） | `exports/*-detect/` | `exports/*-yolo-detect/` |
| 复核页 | `/pose` | `/objects` | `/detect` |
| 素材本体 | 引用 `images/` + 池账本 `.autolabel/pool.json`（同一份，三库共读） | 同左 | 同左 |

三个库的差异全部写在 `library.LIB_SPECS` 一张表里（标签目录 / 元数据目录 / 索引前缀 / 任务类型 / 计量单位），新增加一个库就是加一行表，而不是在几十个文件里各改各的。

- **素材池 = `images/` 目录 + `.autolabel/pool.json` 账本**，不属于任何一库。同一帧被几个模块用到都只落盘一次：跨库导入若指纹命中池里已有文件，直接引用同一份（命令行输出与批次备注里的「复用素材池 N」就是这个数），不复制、不占双份空间。分类、来处、还剩多少没入库都在池这一层说清，界面是 `/pool` 那一页。
- 每个库只记自己的状态：姿态库条目只有 `status/objects/score/flags...`，提示词库条目只有 `prompt_*`，目标检测库条目只有 `detect_*`，同一套统计代码对三库都成立，主页三本账不会互相掺水（顶层那个无前缀的 `labeled` 是姿态库的，跨库统计千万别拿它当某个库的小计）。
- **批次 ID 全局唯一**，`resolve_lib()` 按 ID 自动定位它属于哪个库，接口只需要传批次号。
- 「未分组」在每个库各有一个桶，行 ID 是 `__ungrouped__:pose` / `__ungrouped__:objects` / `__ungrouped__:detect`；裸写 `__ungrouped__` 等价于三个库一起清。
- 主页批次行里的骨骼/检测框两列走**跨库视图**（`_cross_view()`）：同一素材被几个库同时引用时，骨骼列取姿态库、检测框列取两个出框库的并集，保证「批次行小计 = 展开文件清单的逐张汇总」。库级统计（顶部统计卡、模块卡）仍只读本库，不做合并。
- 老数据集升级：`python3 -m autolabel migrate <数据集>` 把旧版单索引里的 `prompt_*` 条目与 `prompt_originals/`、`prompt_history/` 拆进 `objects/`，按批次归属归位 `batch_id`，可重复执行（幂等）；复核服务启动时也会自动做一次。
- 没有 `prompt_*` 可搬时（纯姿态数据集从没跑过提示词标注）也要保证提示词库索引存在：`library.ensure_objects_index()` 补一本空的（数据集名沿用姿态库），文件名记进 `migrate()` 的 `created`。少了这一步，`ReviewStore` 读不到两本索引会抛 `FileNotFoundError`，纯姿态数据集的网页直接打不开。
- **目标检测库不需要迁移**：它是新库，老数据集里本来就没有它的东西，索引与 `classes.json` 在该库第一次被读写时现建（`meta_dir_for()` + 索引补齐）。老数据集升上来不用跑任何命令。

## 索引结构

三套索引结构相同、字段按库加前缀：姿态库 `.autolabel/index.json`（下表 `status/objects/...`，历史上不带前缀）、提示词库 `.autolabel/objects/index.json`（`prompt_*`）、目标检测库 `.autolabel/detect/index.json`（`detect_*`）。素材的公共信息（`width/height/bytes/sha256/dhash/source/video/batch_id/imported_at`）各库存一份，互不覆盖；键名前缀由 `library.LIB_SPECS` 给出，代码里一律走 `field_key(lib, name)`，不手拼字符串。

数据集级：`name`、`class_names`、`kpt_shape`、`flip_idx`、`keypoint_names`、`label_format`、`visibility_meaning`、`settings`（含 `signature` 与完整标注参数）、`last_labeled_at`、`created_at`、`updated_at`、`version`、`items`。

每张图片（`items[<相对路径>]`）：

| 字段 | 说明 |
| --- | --- |
| `width` / `height` / `bytes` | 尺寸与体积 |
| `sha256` / `dhash` | 精确去重 / 感知去重指纹 |
| `status` | `unreviewed` / `edited` / `approved` / `rejected` |
| `objects` | 人数（`null` 表示尚未标注） |
| `score` / `visible_ratio` | 平均置信度 / 可见关键点比例 |
| `flags` / `object_flags` | 图片级 / 单个人级 QC 标记 |
| `label_signature` | 标注参数指纹，用于断点续跑与失效判定 |
| `imported_at` / `labeled_at` / `reviewed_at` | 各环节时间 |
| `source` | 导入前的原始路径 |
| `video` / `time_sec` / `frame_index` / `video_fps` | 视频帧回溯信息 |
| `batch_id` | 所属批次；为空即「未分组（历史导入）」 |
| `recovered_at` | 启动对账补回来的时间（正常导入的图没有这个键） |

提示词库索引里的 `prompt_*` 键（姿态库里没有这些键，反之亦然）：

| 字段 | 说明 |
| --- | --- |
| `prompt_objects` | 检测框数量（`null` 表示还没标过） |
| `prompt_status` | `unreviewed` / `edited` / `approved` / `rejected` |
| `prompt_classes` | 这张图用到的类别号（升序） |
| `prompt_score` | 框的平均置信度 |
| `prompt_flags` | 图片级质量标记，见 `09-提示词标注.md` |
| `prompt_manual` / `prompt_manual_boxes` | 人工补画框的数量 / 下标列表。YOLO 5 列存不下"这条是人工画的"，重读磁盘时靠下标把 `manual` 标记贴回去，**别手改标签文件的行顺序** |
| `prompt_profile` / `prompt_signature` | 用哪条多模态配置标的、字段+描述+配置的签名，用于「同签名跳过」与 `prompt_stale` 判定 |
| `prompt_error` | 上次标注失败的原因 |
| `prompt_priority` / `prompt_reviewed_at` | 复核优先级（由标记加权算出，不落盘） / 最后复核时间 |

目标检测库索引里的 `detect_*` 键（字段含义与 `prompt_*` 一一对应，只是来源从大模型换成了本机权重）：

| 字段 | 说明 |
| --- | --- |
| `detect_objects` | 检测框数量（`null` 表示还没标过；`0` 是标过且真的一个框都没有） |
| `detect_status` | `unreviewed` / `edited` / `approved` / `rejected` |
| `detect_classes` | 这张图用到的类别号（升序，来自**本库登记表**不是权重自带编号） |
| `detect_score` | 框的平均置信度 |
| `detect_flags` | 图片级质量标记 |
| `detect_manual` / `detect_manual_boxes` | 人工补画框的数量 / 下标列表（YOLO 5 列存不下「这条是人工画的」，重读磁盘时靠下标贴回 `manual`，**别手改标签文件的行顺序**） |
| `detect_model` | 出这批框用的权重文件名 |
| `detect_signature` | 标注参数指纹（权重 + 勾选类别 + 阈值），用于「同参数跳过」与过期重标。**换设备不改它**，所以从 MPS 换到 CUDA 不会让已标好的图重跑 |
| `detect_error` | 上次标注失败的原因（坏图不拖垮整批，失败原因逐张记） |
| `detect_labeled_at` / `detect_reviewed_at` | 最后标注 / 最后复核时间 |
| `detect_priority` | 复核优先级（由标记加权算出，不落盘） |

## 批次记录（`.autolabel/batches.json`）

批次分三张表登记：姿态库 `.autolabel/batches.json`、提示词库 `.autolabel/objects/batches.json`、目标检测库 `.autolabel/detect/batches.json`，三表里的 `id` 合起来全局唯一（库由批次 ID 反查，不必传参）。每条批次：`id`、`name`、`kind`（image/video/pose/prompt/prompt_upload/detect/detect_upload/pool/mixed）、`source`（upload/cli/pool）、`module`（`pose` / `objects` / `detect`，归属哪个二级模块）、`status`（running/done/cancelled/failed）、`created_at` / `finished_at`、`params`（模型、抽帧参数等）、`uploads`（提交的文件名）、`items`（成员图片相对路径）、`message`（含「导入 N 张（复用素材池 M）」这类入库口径）。

`module` 决定批次在哪个模块的列表里出现：写入时按任务类型推导（`prompt*` → `objects`，`detect*` → `detect`，`image`/`video` → `pose`，从素材池认领 → 目标库），历史批次没这个字段也在读的时候按 `kind` 现补（`module_for()`，老值 `prompt` 自动当 `objects`），认不出的归到「未识别」，不会出现漏网的批次。`_row()` 同时给出 `pose{}` / `prompt{}` / `detect{}` 三个分组和原来的扁平字段，老界面照旧能读。

生命周期：`create_batch` → 导入成功后 `attach_items` 写 `batch_id` → `finish_batch` 收尾；统计（图片/已标/人体/待复核）不落盘，读的时候按索引现算，所以人工改状态后列表立即准确。

删除有两个粒度，都先写 `deleted/` 快照、按需重算坐标与 QC 报告：`delete_batches` 整批删（本库标签/QC 叠加图/originals/history + 索引条目 + 批次记录）；`delete_images` 按张删，只动选中的图，并从所属批次的 `items` 里摘除——**批次是否已被删空以索引为准**，登记表 `items` 因导入中断偏少时不会把还有图的批次误删。逐张删完恰好清空时才顺手移除批次记录，没被这次删除碰过的批次（包括 0 张的空批次）一律不动。

按张删再分**两种力度**（`delete_images(mode=...)`，界面上是「连素材文件一起删」勾选框）：

| 力度 | 行为 | 素材文件 |
| --- | --- | --- |
| `lib`（默认） | 只摘本库的索引条目、标签、复核记录、撤销快照，并从本库批次 `items` 里移除；另外两个库的标注完全不动 | 留在 `images/`，别的库继续用 |
| `purge` | 三个库一起摘引用并删各自的标签，再删 `images/` 里的素材文件 | 删掉（`keep_files=True` 时仍保留素材） |

素材文件只有在**其余库都不再引用**时才真删（`_maybe_remove_pool()`）；返回体里的 `items` 是受影响的素材张数、`removals` 是「库 × 图」的引用数、`files_removed` 是清掉的文件数、`libs` 是涉及哪些库、`snapshot` 是快照路径。

批次表是「读全表 → 改 → 写全表」，而命令行与复核服务是两个进程，所以写路径统一走 `_file_lock(root)`：`.autolabel/batches.lock` 上的 `flock` + 进程内 `RLock`，且**按线程可重入**（`reconcile_with_disk()` 握锁期间还会调 `attach_items()`，flock 按文件描述符判归属，不可重入会自己把自己锁死）。

外部进程超时：`ffprobe` 60 秒（超时降级成「元信息未知」，任务继续），抽帧 `min(3600, max(300, 300 + 片段秒数 × 4))`，`AUTOLABEL_FFMPEG_TIMEOUT` 覆盖全局，超时抛中文提示并保留已入库的帧。

取消语义：排队任务直接出队并删上传临时文件；运行中任务在阶段边界和每张图前检查 `cancel_requested`（`JobCancelled` / `label_dataset(should_stop=...)`），标完当前图才退出，批次状态记 `cancelled`。

## 素材池账本（`.autolabel/pool.json`）

三个键：`categories`（分类表：`id`/`name`/`note`/`icon`/`created_at`，上限 40 个、名字 24 字、备注 80 字，图标只能从 sprite 里那五枚里挑）、`batches`（**池导入批次**，ID 一律 `p_` 前缀，字段与库批次表同一套词）、`items`（每张素材一笔，键是 `images/` 下的相对路径）。

`items` 只在两种情况下记账：**被分了类**，或者**只进了池还没有任何库引用**。后者必须记——不然下次导入认不出它是重复帧，启动对账也会把它当孤儿图抢进姿态库。已经进了库的素材以各库 `index.json` 为准，池账本只往里补素材层字段（`sha256/bytes/width/height/dhash/imported_at/source/video`，即 `POOL_ITEM_KEYS`），`status` 这类标意义的值绝不写进池账本：同一张图在姿态库已复核、在检测库还没标，谁也不该覆盖谁。

几条不变量（都有测试钉着）：

- **只要文件还在 `images/` 且没有任何库引用它，池账本就必须有这一笔**。删素材时勾了「保留原图」（`mode=lib` / `purge + keep_files`）走的是 `keep_tracked_in_pool()`：缺什么补什么，哈希没有就现算（哈希是去重的唯一依据，漏一次同一视频抽两遍就落双份）。
- **文件真删了，账本条目跟着删，批次 `items` 同步瘦身**：`prune()` 把删掉的素材从所属池批次的 `items` 里摘掉，素材全删光的批次行一起删（否则素材池「按来处」会留一排点进去空白的 0 张批次）；正在导入、`items` 本来就空的批次不动。
- **取消分类不留空壳**：`assign(category="")` 会把 `category` 与 `assigned_at` 一起抹掉，条目空了就整条删掉。
- **忘掉来处不留悬指**：`forget_batch()` 删批次行时，把还指着它的素材一并抹掉 `batch`，返回 `detached`。
- 删除入口按前缀分流：`delete_batches()` 收到 `p_xxx` 走池那套，混选（池批次 + 库批次一起勾）两份结果合并成一句回话。

## 标签格式

一行一个人：`class cx cy w h (x y v)*17`，全部归一化到 0~1，浮点保留 6 位。空文件 = 背景图。

可见性：`0` 不监督，`1` 遮挡但**参与**监督，`2` 可见。ultralytics 判定为 `kpt_mask = v != 0`。

## 检测框标签的轮廓尾列

目标检测库的一行是 `class cx cy w h [x1 y1 ... xn yn]`：前 5 列与 YOLO detection
逐字节相同，**轮廓是挂在后面的尾列**（归一化，浮点同样 6 位）。这么放的理由是方框才是本库
可编辑的主体（补画 / 拖动 / 去重 / 复核签名都按方框算），只读 5 列的老逻辑拿到的是同一个框，
老数据集零迁移。读的时候尾列坏了静默当没轮廓（`parse_polygon`），坏成什么样由
`autolabel validate` 报（`bad_polygon` / `poly_range`）；标准分割行
（`class x1 y1 ...`）只在导出训练集时写（`format_segment_row`），
`data.yaml` 相应标 `task: segment`。提示词库永远只有 5 列——多模态大模型给的是方框不是 mask。

## 检测框两套库的列口径

提示词库与目标检测库共用 `collect_object_records()` / `render_object_coords()`，
但**坐标产物里 `meta.json` 的列说明按库各写一份**（`object_column_doc(lib)`）：
提示词库那份讲 `prompt_status`/`prompt_stale`/`vlm_failed`，检测库那份讲
`detect_status`/`model_stale`/`model_failed`/`masked`。以前两库共用一份说明，
检测库导出的 CSV 会拿 `prompt_stale` 教人，对着一列 `detect_*` 找不到北。

## 后台任务与并发

- `JobStore` 串行执行任务（`Semaphore(1)`），避免反复加载模型；任务状态在内存里保留最近 20 条，`kind` 分 `image` / `video` / `pose` / `prompt` / `prompt_upload` / `detect` / `detect_upload`，五类「素材已在库里」的批量任务只接受该库索引里真存在的图（`_known_images` 按 `lib` 查，认错的库会在这里被剔掉）；`pose` / `prompt` / `detect` 三类支持 `only`（界面圈定的那批图），传到 `label_dataset(only=...)` 是**在扫描源头**跳过范围外的图，不是跑完再挑；`prompt_upload` 是提示词模块的「上传 + 标注」一条链（入库 → 逐图标注 → 出坐标 → 收尾批次），只入库不标注时不校验字段与多模态配置。
- `ReviewStore.__init__` 先按库做一次 `migrate()`（老布局自动升级，已分库就跳过；顺带保证两本索引都在，见 `ensure_objects_index()`），再调 `batches.reconcile_with_disk()` 逐库对账：补回 `images/` 里已落盘但索引缺席的图片、挂到那个还"标注中"的批次上、把无人认领的 running 批次改成 `interrupted`；**对账按库排队**，某库还在标注时另一个库不许抢走它刚落盘的孤儿素材（`_should_claim()`）；`--keep-files` 删除批次留下的文件按删除快照里的清单排除，不会被误当成孤儿。**对面库的索引在每轮对账里只解析一次**（以前扫到每张图都重读一遍整个 `index.json`，1500 张就要 1 秒、两万张要几分钟）。对账结果通过 `/api/dataset` 的 `recovery` 字段给工作台提示条，并打到启动日志。
- 写索引统一走 `ReviewStore._mutate()`：**一把锁里**完成「按磁盘对齐内存 → 改单条 → 整表落盘」。以前是 `reload()`（拿锁再放锁）之后再 `with lock:` 改+存，中间那段空隙里别人改过盘就会被旧副本整表抹掉（索引是覆盖写，没有字段级合并）。删除 / 认领 / 删字段这三处直接改盘的助手原先不参与这把锁，现在用 `_mutate(resync=True)` 挤进来，收尾再按磁盘对齐一次内存。
- 锁序固定 `ReviewStore.lock → batches.lock`；`ReviewStore.lock` 是 `RLock`（`_mutate` 里要重入），后台任务线程只在没持任何锁时才调 `reload()`。已知边界：任务写索引走 `pipeline`/`prompt` 自己的 `load_index → save`，不持 `ReviewStore.lock`（持住会横跨整段推理、把界面锁死几秒），所以任务跑动期间恰好删图仍有小概率互相覆盖，窗口已从「整段计算时间」压到「写盘那几毫秒」。
- 读路径也要新鲜：`dataset_payload()` 先跑 `_refresh_if_changed()`，按 `.autolabel/index.json` 的 `mtime_ns + size` 指纹判断磁盘索引是否被外部改过（`autolabel import`、另一个终端的 `autolabel label`、后台任务落盘），变过才重读，没变零开销。否则服务常驻内存的索引会让命令行导入的图一直显示 0 张。
- `label_dataset` 逐图攒 `updates`，每 25 张与结束时 `load_index` 后按图合并再保存，人工在标注期间点的接受/驳回不会被整体覆盖。
- 前端在任务进行期间锁住编辑按钮，任务结束自动刷新列表。
- 「清除任务」（`JobStore.clear()`）是协作式取消：排队任务直接出队并删除上传临时文件，运行中的任务在阶段边界与每张图前检查 `cancel_requested`（`JobCancelled` / `label_dataset(should_stop=...)`），标完当前图才退出，取消后仍会补一次坐标文件生成。

## 模型权重与镜像

- 权重统一放在 `models/`，`resolve_model_path("yolo11m-pose.pt")` 会把裸文件名解析到该目录，避免权重散落在工作区根目录。
- `weights_ready()` 用 zip 尾部目录判断完整性；`model_inventory()` 给界面报出每个候选权重的大小与就绪状态。
- `ensure_weights()` 在权重缺失或不完整时经镜像下载：默认前缀 `https://gh-proxy.com/`，用 `AUTOLABEL_WEIGHTS_MIRROR` 覆盖（设成空串回到直连），支持 Range 续传，落盘先写固定的 `x.pt.part`（重启后还能接着下）、校验长度与 zip 完整性后再改名。两处细节：服务器**收了 `Range` 却回 `200` 整包**时按整包重算总量（否则永远判「下载不完整」，重下也解不开）；同一个 `.pt.part` 由 `claim_download()` 的文件锁独占，两个实例同时点下载时后到的一方等前者下完、不重复下载。半截的 `.part` / `.bad` 由 `partial_paths()` 报给界面显示，删权重时连带清理。
- `PoseBackend.load()` 加载失败会自动挪开坏文件（`*.bad`）经镜像重下一次；再失败才抛 `weights_hint`，附带文件体积与 `rm` 命令。

## 模型管理（`models.py`）

三层数据，一份清单：`PRESET_CATALOG`（姿态精选 13 档，逐档核对过参数与 mAP，中文说明写死在代码里）+ `configs/models.json`（本机状态）+ `configs/vlm.json`（多模态配置），由 `ModelRegistry` 合成界面与命令行共用的统一清单。搜索用的完整目录（160 档，五种任务）在 `modelhub.py`，精选条目永远优先于宽目录模板。清单还会把 `models/` 里**真有文件但目录与登记表都不认识**的权重补成行（`_disk_rows()`）——刚拷进来的权重不该因为「我们不认识」就在下拉框里消失。

- **内置目录** `PRESET_CATALOG` / `catalog()` / `catalog_downloadable()`：YOLO11 n/s/m/l/x → YOLOv8 n/s/m/l/x → YOLO26 n/s/m，顺序即展示顺序；每档带中文说明、参数规模、mAP50-95、预计体积、SHA256、关键点集、速度与适合场景。官方没公布的字段留 `None`（YOLO26 的参数与精度、部分档位的 SHA256），说明文案里直说「官方暂未公布」，不编数字。`configs/models.json` 的 `catalog.<ID>` 可覆盖/追加/隐藏条目。
- **登记表** `configs/models.json`（`AUTOLABEL_MODEL_CONFIG` 可换路径）：`defaults` 默认模型、`catalog` 目录条目的本机覆盖（改名 / 隐藏）、`local` 登记的本地模型、`downloads` 下载记录（上限 50 条）、`last_used` 最后使用时间、`metadata` 加载实测元数据。纯本机状态，没存 Key，删掉只丢默认值与记录。老配置里残留的 `notes` 键不再读，也不再写回。
- **统一清单** `models()`：目录行 + 本地登记行 + 多模态行，每行补 `status`（可用 / 未下载 / 文件不完整 / 不兼容）、`source`（内置目录 / 已下载 / 本地 / 外部服务）、`compatible` 与中文理由、`note`、`last_used`、`default`。`weight_overlay()` 给老权重行补同一批字段，`source` 仍保持 `disk|preset` 语义不破坏既有前端。
- **兼容性** `compatibility()`：数据集关键点数量与模型输出点数不一致、权重不完整、多模态最近测试失败或没测过 → 判不可用并给出中文理由；`record_metadata()` 在加载后把实测关键点数/设备/版本写回登记表，排查时不靠猜。
- **写操作** `set_default()`（按能力分别记，跨能力拒绝）、`register_local()`（只记路径不动文件，要求姿态权重是完整 zip 包，已在目录里的直接说「本来就在」）、`forget()`（只删登记条目，内置目录项拒绝）、`record_use()` / `record_download()`（失败都不打断标注与下载）。给模型写备注的 `set_note()` 连同 `/api/models/note` 一起删了：目录里的中文说明是唯一口径，那列十行有九行是空的。
- **任务标签** `task_hint()` 按文件名推出 `(task, 中文名)`，开放词表那一族在这里补上「开放词表（YOLOE / YOLO-World）」；界面那枚类别徽标和 `--info` 的任务行都读它。因为 `modelhub` 顶部 import 了 `models`，这两个方向相反的引用必须延迟导入。
- **权重文件** `weight_names()` 扫描 `models/` 得到清单：界面预置的 n/s/m 排在前面，用户自己放进来的自定义权重跟在后面；只有 `.pt.part` / `.pt.bad` 残留的名字也会被列出，方便清垃圾。
- `delete_weight()` 只接受权重目录里的裸文件名（带路径直接拒绝），连同 `.part` / `.bad` 一起删；`active_names` 由复核服务按未完成任务的 `params.model` 传入，正在用的权重删不掉。
- `start_download()` 每个权重同时只有一个后台线程，进度写回任务表（`stage` / `percent` / `message` / `error`），界面轮询 `POST /api/models/download` 显示。
- 多模态大模型配置在 `configs/vlm.json`（`AUTOLABEL_VLM_CONFIG` 可换路径），字段与预设见 `02-命令行参考.md`。**配置文件里不落明文 Key**：`save_vlm()` 写盘前摘掉 `api_key`，明文进 `~/.autolabel/secrets.json`（`AUTOLABEL_SECRETS` 可换路径），配置只存 `key_ref: vlm:<配置ID>`；`load_vlm()` 读盘时才把明文回填到内存，`_migrate_keys()` 会把老配置里残留的明文自动搬走并回写。界面回显一律 `public_profile()` 掩码，写回掩码或空串表示保持原 Key 不变。
- `test_profile()` 先 `GET {base_url}/models`，拿不到结果再退化成一次 `max_tokens=1` 的 `POST /chat/completions`；失败原因翻译成可执行的下一步（服务没起 / Key 不对 / 地址少了 `/v1` / 额度不足）。
- `find_profile()` 支持按配置 ID 或名称（含前缀）查找，给命令行 `--vlm` 用；找不到时错误里列出可选项。

## 模型目录与搜索（`modelhub.py`）

`models.PRESET_CATALOG` 只有姿态一档（13 条），界面要按任务搜检测 / 分割 / 旋转框 / 分类时没数据可用。`modelhub.py` 在**不往 `models.py` 里塞第二份目录**的前提下补一层目录 + 搜索（`models.py` 只多了一个 `hub_catalog` 键，存「更新目录」拉回来的官方清单缓存）：

- **五种任务**：`TASK_VALUES = pose / detect / segment / obb / classify`，`TASK_LABELS` 给中文名（人体姿态 / 目标检测 / 实例分割 / 旋转框检测 / 图像分类），数组顺序即界面分组顺序，姿态在最前。姿态那 13 条从 `models.PRESET_CATALOG` **原样带过来**（`map_pose` / `preset_visible` 这些字段现有代码还在读，一个都不减）。
- **数字必须有出处**：其余任务的体积按 `ultralytics/assets` release v8.4.0 的实际字节数填，全部经 HEAD 请求核实，条目带 `size_verified`；参数规模与精度取 Ultralytics 官方模型表（2026-10 版），官方没给的填 `None` 并在中文说明里写明，不编数字。`sha256` 只填本机 `models/` 里已有文件的真实值，其余留空串——留空就跳过校验，不会拿错的哈希去否掉一个好文件。
- **每行自带前端字段**：`task_label` / `intro` / `params` / `bytes` / `url` / `installed` / `classes_note`（这个权重的类别表是什么规模），前端不必再做一次字段改名；`capability` 与 `task` 同值，姿态仍是 `models.CAPABILITY_POSE`，其余任务用任务名本身。
- **离线是主路径**：`search()` 纯本地匹配，一个网络请求都不发；`search_remote()` / `search_payload()` 才连 GitHub。断网、超时（6 秒）、限流一律 `ok=False` 并在 `note` / `error` 里写清原因、照常返回本地结果，**绝不抛异常**——搜索框不能因为没网就红一片。
- **下载不另起一套**：`start_download()` / `backends.ensure_weights()` 是唯一下载路径，`modelhub` 只负责「找到它、说清它是什么」。
- `autolabel models --search 关键词 [--task 任务] [--remote]` 与界面搜索框读同一层，两个入口口径一致。
- **`refresh_catalog()` 是「更新目录」的唯一实现**：目录本体（`WIDE_MANIFEST`）仍是写死在代码里的静态清单，刷新只往 `hub_catalog` 写一层**覆盖表**（`文件名 → 字节数` + 版本号 + 核对时间），`_base_rows()` 末尾 `_merge_release()` 把它并进目录。重复刷新幂等：上次补进来的档位算进「已认识」，同一版再刷不会重复报「新增 N 档」；清单整份替换，官方删掉的档位缓存里跟着没有。`refresh_supported()` 挡住本软件没有入口的分支，`use_assets_release()` 把下载基址对齐到缓存那一版（新档位只存在于最新 release，地址按老版本号拼必然 404）。

## 多模态标注后端（`vlm.py`）

`backends.build_backend(settings)` 按参数挑后端：`settings.vlm_profile` 为空返回 `PoseEnsemble`，非空返回 `VLMBackend`。两者接口一致（`load()` / `infer(image) -> List[Person]` / `display_names`），`pipeline.label_dataset` 不需要分支。

- 提示词写死 COCO-17 顺序与可见性语义，要求只回 JSON，坐标按 0-1000 整数回报；`parse_people()` 里 0-1 小数也认（按数值范围判尺度）。
- 图片按该条多模态配置的 `image_limit`（默认 1024）缩边后编成 JPEG data URL，控制请求体；`max_tokens` 与 `json_mode` 同样按配置取值。
- 解析分两级：先整段 `json.loads`，失败就退化成按 `keypoints` 数组做括号平衡扫描 + 三元组正则提取，所以漏逗号、缺尾括号、被截断的回复都能救回一部分。
- 点数不足补 `v=0`，全零点视为未标注，bbox 用 `expand_bbox_with_keypoints()` 撑到包住所有可见点。
- 输出统一打 `vlm_labeled` 标记（QC 权重 1.5）、`score=0.5`，索引 `labeled_by` 写 `vlm:<配置ID>`，与 YOLO 标注可区分。
- `chat()` 输出上限 4096 token、等待至少 60 秒；正文为空时回落到 `reasoning_content`（思考型模型常把结论只写在思考里）。
- 单张失败由 `label_dataset` 捕获，计入 `failed` 并继续下一张，不中断整批。
