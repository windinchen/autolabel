# 视频与批量导入

## 在哪上传

两个模块各有各的上传口，视频、图片、整个图片目录三种都能拖：

| 场景 | 做法 |
| --- | --- |
| 骨骼标注，少量素材不想敲命令 | `/pose` 右上角 **导入素材**（快捷键 `W`），或主页「姿态标注」卡上的 **去导入素材** |
| 物品检测框，少量素材不想敲命令 | `/objects` 右上角 **导入素材**（快捷键 `W`），或主页「提示词标注」卡上的 **去导入素材** |
| 素材另一个模块已经传过 | 上传弹层里的 **从素材池添加**：直接引用 `images/` 里那份文件，不重传、不复制 |
| 一批图片 | `python3 -m autolabel import <数据集> 目录A 目录B --dedupe exact [--lib pose\|objects]` |
| 一段/多段视频 | `python3 -m autolabel video <数据集> 录像.mp4 --fps 0.5 [--lib pose\|objects]` 或 `auto` 一把梭 |
| 池里有什么、还差哪个库 | `python3 -m autolabel pool <数据集>`，认领用 `--add images/a.jpg --lib objects` |

默认 `--lib pose` 进姿态库；提示词标注的素材用 `--lib objects`，目标检测的素材用 `--lib detect`。几个库落进同一个 `images/` 素材池：同一帧只落盘一次，命令行与批次备注里的「复用素材池 N」就是省下的次数，素材要等所有库都不再引用才真删。

`auto` 支持混合提交，按扩展名自动分流：

```bash
python3 -m autolabel auto datasets/myset 录像1.mp4 录像2.mov ~/Pictures/人像 --fps 0.5
# 想直接喂给提示词标注：加 --lib objects（只入库并收尾，不跑 YOLO-pose，随后接着跑 prompt）
python3 -m autolabel auto datasets/myset ~/Pictures/瓶子 --lib objects
python3 -m autolabel prompt datasets/myset --fields bottle --coords
```

## 抽帧策略

```bash
# 定帧率：0.5 = 每 2 秒 1 帧
python3 -m autolabel video $D 录像.mp4 --fps 0.5 --max-frames 600

# 场景切点：按镜头切换取帧，适合剪辑过的素材
python3 -m autolabel video $D 录像.mp4 --scene 0.3

# 只取某一段
python3 -m autolabel video $D 录像.mp4 --start 12 --duration 30 --fps 1
```

选型建议：

| 素材 | 建议 |
| --- | --- |
| 固定机位、动作缓慢 | `--fps 0.5 --dedupe perceptual`，能砍掉 60% 以上冗余帧（默认不去重，张数会多一些） |
| 剪辑/MV/多镜头 | `--scene 0.3`，切点处取帧 |
| 快速动作（球类、舞蹈） | `--fps 2 --video-dedupe none`，保留时序细节 |
| 需要连续帧做骨架平滑 | 同上，去重关掉 |

## 时间戳回溯

每帧在索引里记 `video`（源视频绝对路径）、`time_sec`（原视频时间点，秒）、`frame_index`（抽帧序号）、`video_fps`，并写进 `coords.csv` / `coords.jsonl`。发现某帧标注错了，可以直接跳到原视频对应时间点复查。

```bash
# 用时间戳直接定位到原视频
ffplay -ss 12.5 "样本/1792122145367.mp4"
```

## 去重

- `exact`：按 SHA-256 精确去重。**图片导入与视频抽帧的默认**——只跳过字节完全相同的帧。
- `perceptual`：dHash64 汉明距离 ≤ 5 算同一画面，只留 1 张。视频抽帧**不再默认用它**：抽出来的帧本来就是按时间挑过的，同场景的多条录像会互相吃掉（实测 5 条同机位录像抽出 256 帧只剩 48 帧）。只想省张数时再手动选。
- `none`：全部保留。

界面里那一档「帧去重」和命令行的去重参数是同一套三档：只跳过完全相同的帧（默认）/ 近似去重（画面相近只留 1 张）/ 全部保留。`auto` 里图片归 `--dedupe`、视频帧归 `--video-dedupe`；`video` 命令只有帧，`--dedupe` 与 `--video-dedupe` 是同一个参数的两种写法。

## 大小与数量上限

| 项 | 默认 | 调整方式 |
| --- | --- | --- |
| 网页单文件上传 | 1024 MB | `review --max-upload-mb` |
| 单视频抽帧数 | 600 | `--max-frames` / 界面「最多帧数」（同一个默认，界面不再另设 300） |
| 导入图片最长边 | 1600 px | `--max-side` |
| JPEG 质量 | 95 | `--jpeg-quality` |
| 抽帧等待上限 | `min(3600, max(300, 300 + 片段秒数 × 4))` 秒 | 环境变量 `AUTOLABEL_FFMPEG_TIMEOUT`（秒） |

超大视频建议先命令行 `video` 抽帧，或用 `--start/--duration` 分段，避免一次上传几百 MB。

上传是**分块落盘**的（1 MB 一块），不会像以前那样先把整个文件读进内存——传 1 GB 的视频不再顶出 1 GB 瞬时内存去跟 torch 抢地方。超上限时服务端会把请求体读干净再回 413，界面能正常显示「单个文件超过 N MB 上限」，而不是含糊的「网络错误」（以前先断开连接，客户端还在往里写，只能看到断链）。

## 批次与回退

`import` / `video` / `auto` 每次执行都会登记一个批次（`--batch-name "十月聚会"` 自定义名字），复核界面按 `B` 或命令行 `batches <数据集>` 都能按批次查看。素材不满意就整批删：`python3 -m autolabel batches <数据集> --delete <批次ID>`，会连图片、标签、QC 叠加图、复核历史一起删掉，并在 `.autolabel/deleted/` 留快照。

## 实测

真实手机视频（29 MB，竖屏）：`--fps 0.5 --max-frames 60` → 抽出 11 帧，默认全部入库；换 `--dedupe perceptual` 只剩 2 帧，标注 14 个人、238 个关键点，端到端约 3 秒（MPS + 双模型）。
