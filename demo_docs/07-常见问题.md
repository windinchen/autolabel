# 常见问题

## 网页打不开，或者打开后一张图都没有

分两种情况，先看浏览器地址栏能不能连通：

- **提示「无法访问 / 拒绝连接」**：复核服务没在跑。它是前台进程，关掉终端或按 Ctrl+C 就停；用后台方式起的进程也可能随会话结束被回收。在自己终端里重新起一个：`python3 -m autolabel review datasets/demo`（默认 8765 端口并自动开浏览器，只想起服务加 `--no-browser`，端口被占用加 `--port 8766`）。
- **页面能打开但中间是空的**：这个数据集里已经没有图片了。删素材时没加 `--keep-files`（界面「删除所选」同理）会连图片文件一起删，索引里只剩 0 条。页面中间现在会明确写「这个数据集还没有图片」，按提示拖文件进来、点「上传素材」，或命令行 `autolabel import` 补图即可。

先确认页面加载的是哪个数据集、还剩几张：看工作台标题「工作台 · <数据集名>」与「等你复核」那一格，或姿态标注页标题「姿态标注 · <数据集名> (N 张)」，N 是当前图片数。被删的素材记录还能按下面「批次删错了怎么找回」恢复。

## 选了更大的模型后报 `PytorchStreamReader failed reading zip archive`

首次选 `yolo11s/m-pose` 要联网下载权重，下到一半断网或复核服务被重启，就会留下一个半截文件。现在有三层兜底，一般不用手动管：

1. **走镜像下载**：默认经 `https://gh-proxy.com/` 拉权重（直连 GitHub 经常只有 10 KB/s 甚至连不上），失败自动重试并保留 `.part` 续传。
2. **加载失败自动重下**：真的遇到坏文件时，先把旧文件挪成 `*.bad`，经镜像重下一遍再加载；成功后删掉 `.bad`。
3. **报错了才要人工管**：重下仍失败才抛错，且直接写出文件体积和修复命令。

下拉框旁边会实时显示每个权重的状态（`已就绪 40.5 MB` / `未下载` / `权重不完整`），任务日志里也会写明「正在下载权重（已下载 X MB）」，不会再看着像卡死。

```bash
# 换镜像（留空即直连 GitHub）
AUTOLABEL_WEIGHTS_MIRROR=https://ghfast.top/ python3 -m autolabel label datasets/xxx --model yolo11m-pose.pt

# 手动重来
rm models/yolo11m-pose.pt
python3 -m autolabel label datasets/xxx --model yolo11m-pose.pt
```

## 批次删错了怎么找回

`.autolabel/deleted/<时间戳>.json` 里有被删条目的完整索引字段和标签原文（目录只保留**最近 200 份**快照，大约等于最近 200 次删除动作；更早的删除如果想找回，只能靠自己的备份）（`label_lines`），并按库分别记录（`lib` 与两库各自的标签），所以从提示词库删的框不会只写进姿态库那份。把图片文件放回 `images/`、标签文本写回 `labels/同名.txt` 或 `prompt_labels/同名.txt`，再执行一次 `import`（配 `--lib` 指到对应的库，`--dedupe exact` 会自动跳过重复、只补索引）或直接用 `label` / `prompt` 重标即可。坐标与 QC 报告在删除时已重算，恢复后重新 `coords` / `qc` 一次。

## 想按上传批次清理不要的素材

主页「批次管理」勾选批次 →「删除所选批次」（姿态页按 `B` 打开的是姿态库自己的批次）；命令行 `python3 -m autolabel batches <数据集>` 看列表（`--lib pose/objects` 只看一个库），`--delete <批次ID>` 删除，`--keep-files` 只删记录保留素材。批次 ID 全局唯一，删哪个库由 ID 自动判定；素材文件只有在另一个库不再引用时才会删，否则只摘本库引用。

正在标注的批次默认删不掉：界面会看当前有没有真在跑的任务，服务重启后遗留的「标注中」批次可以直接删；命令行看不到服务状态，需要加 `--force` 才放行。

## 怎么配本地/云端多模态大模型

顶部导航的 **模型管理**（或按 `M`），下半部分是「多模态大模型」：选类型（本地 / 云端）→ 选服务类型（Ollama、LM Studio、vLLM、OpenAI 兼容、阿里云 DashScope、自定义）→ 填服务地址和模型名 → 点 **测试**。本地服务一般不校验 Key，留空即可；云端必填 API Key。

命令行等价：

```bash
python3 -m autolabel models          # 权重 + 多模态配置一览（含每个配置的最近测试结果）
python3 -m autolabel models --add-vlm '{"name":"本地 Ollama","provider":"ollama","model":"qwen2.5vl:7b"}'
python3 -m autolabel models --test-vlm vlm_a13bdd38
```

服务地址要带到版本号那一层：Ollama 是 `http://127.0.0.1:11434/v1`，LM Studio 是 `http://127.0.0.1:1234/v1`。只写 `http://127.0.0.1:11434` 会在请求 `/models` 时 404，测试文案会直接点出来。缺 `http://` 前缀、末尾多写的 `/` 都会自动补齐去掉。

## 多模态配置「测试」失败怎么办

测试先看 `GET {base_url}/models`（便宜，能列出模型就算通过），拿不到结果再退化成一次 `max_tokens=1` 的对话探测。失败文案带下一步动作：

| 提示 | 处理 |
| --- | --- |
| 连不上 …：本地服务没启动？ | 本地服务没起，Ollama 先 `ollama serve`，LM Studio 打开开发者服务开关 |
| 端口不对 / 地址要写成 …/v1 | 补上 `/v1`，或换成服务实际监听的端口 |
| `401 未授权` | 云端 Key 没填或填错；本地服务随便填几位占位即可 |
| 超时（默认 15 秒） | 大模型首次装载慢，把超时调到 60–300 秒再试 |

测试不通过不拦你保存，但真要用到该配置的环节会跳过它并说明原因。

## 多模态配置存在哪？API Key 会泄露吗？

配置在 `configs/vlm.json`（`AUTOLABEL_VLM_CONFIG` 可换路径），**API Key 明文不在里面**：落盘前会被摘掉，改存 `~/.autolabel/secrets.json`（`AUTOLABEL_SECRETS` 可换路径，权限 0600），配置里只留 `key_ref: vlm:<配置ID>` 这种引用名。所以 `configs/vlm.json` 贴给别人看、甚至提交进仓库都不会泄 Key。

老配置里如果还写着明文 `api_key`，第一次读到就自动搬进 Key 文件并把配置改写成引用名，不用手工清。读盘后明文只在内存里存在，界面与 `/api/models` 返回的仍是掩码（长 Key 形如 `sk-…1234`，短 Key 形如 `0***2`）；重新保存时 Key 输入框留空或仍是掩码，视为不修改，不会把已有 Key 覆盖成空。

## 权重想删掉腾空间，或只留一个

模型管理面板上半部分是「姿态权重」：列出预置 `n/s/m` 与 `models/` 里所有自定义 `.pt`，显示体积、来源和修改时间，勾选后 **删除所选**。被正在运行的标注任务占用的权重删不掉，会提示「正在被标注任务使用」。删掉不影响已有标签，下次用到该权重时自动经镜像重下。

想加非预置权重（如 `yolo11l-pose.pt`）：先看目录再下——`python3 -m autolabel models --browse` 列出 13 档可下载模型和中文说明，面板「模型目录」里直接点 **下载**；也可以把文件直接放进 `models/`，放对目录就识别为自定义权重并出现在下拉框里。仓库外的权重用「登记本地模型」登记，只记路径不搬文件：

```bash
python3 -m autolabel models --browse                              # 挑模型，看中文说明和预计体积
python3 -m autolabel models --download-weight yolo11l-pose.pt     # 下载
python3 -m autolabel models --delete-weight yolo11m-pose.pt --yes
python3 -m autolabel models --register ~/weights/gym.pt --display-name 体操自研
```

详见 `08-模型管理.md`。

## 给模型写的备注、默认模型存在哪？换机器要拷什么？

存在 `configs/models.json`（`AUTOLABEL_MODEL_CONFIG` 可换路径），里面只有本机状态：备注、各类默认模型、登记过的本地模型路径、最近 50 条下载记录、最后使用时间、加载实测元数据。**没有 Key**，删掉只会丢备注和记录，已标注的数据一点不动。

换机器要带走三份东西，权重本体不用拷（下次用到自动重下）：

```bash
cp configs/vlm.json <新机>/configs/            # 多模态配置（不含明文 Key）
cp configs/models.json <新机>/configs/         # 备注 / 默认值 / 本地登记
cp ~/.autolabel/secrets.json <新机>/.autolabel/ # API Key 明文
```

`--register` 登记的是绝对路径，换机器路径变了要重新登记一次。

## 怎么知道哪个模型能用在当前数据集？

```bash
python3 -m autolabel models --dataset datasets/demo        # 或直接看界面「模型目录」
```

关键点数量和当前数据集对不上的模型会标成「不兼容/暂不可用」，理由写成「当前数据集 X 是 17 关键点，该模型输出 26 关键点（COCO-26），标出来的骨骼没法直接和已有标签合并」，上传弹层的下拉框里这类模型直接置灰。权重只剩半截（下载中断、损坏）同样判不兼容。模型真正加载过一次后，实测关键点数、设备、ultralytics 版本会回写进登记表，`models --info <ID>` 里以「加载实测」显示。

## 上传弹层的模型灰着点不动？

- 写着「未下载，先到「模型管理」下载」：正常，未下载的模型不再允许直接选中开跑（以前是点了才下、卡在任务里）。一个都没下载时会放开第一条，选了会在首个任务时自动经镜像下载。
- 写着「与当前数据集关键点数量不匹配」：换成与数据集点数一致的模型，或用 `--dataset` 那条命令看具体原因。

## 多模态大模型标注能替代 YOLO-pose 吗

能标，但当前定位是**补充手段**而不是替代品。上传素材的模型下拉框选「多模态大模型」那组，或命令行 `--vlm <配置名>`，就走大模型标注。

同一张 4 人测试图实测：本地 8B 级视觉模型 38.8 秒标出 2 个人（YOLO11n 约 0.03 秒标出 4 个）。大模型的优势是无需权重、遇到 YOLO 漏掉的姿态也能给点，代价是慢两个数量级、坐标更飘、人数不稳定。

所以每条大模型标注都会打 `vlm_labeled` 标记并进人工复核清单，索引里 `labeled_by` 记成 `vlm:<配置ID>`。要拿它做正式训练集，务必先复核一遍。

## 多模态标注特别慢、或者一直失败

| 现象 | 原因与处理 |
| --- | --- |
| 一张图卡 20~40 秒 | 正常。每张一次网络请求，代码里等待下限已放宽到 60 秒；先用 `--limit 20` 试跑 |
| `模型返回空内容` | 思考型模型把输出额度花在推理上了。把该配置的「回复上限」`max_tokens` 调大（默认 4096）或换非思考模型 |
| `返回的 JSON 残缺到无法解析` | 模型没按格式回。打开该配置的「强制 JSON 模式」（走 `response_format`），仍失败就换指令跟随更好的模型 |
| 大图特别慢 / 请求体超限 | 把「送图最长边」`image_limit` 调小（默认 1024，可低到 256）；细节多的画面反过来调大 |
| `找不到多模态配置 xxx` | `--vlm` 要写「模型管理」里的配置名或 ID，错误信息会列出可选项；界面点「开始上传并标注」时也会先拦下来，不用等任务启动 |
| 标出来人数偏少 | 提示词已要求「不要编人」，遮挡严重的画面本就会少报；这类图会在复核清单里，按 `X` 删误检、拖框补漏检 |

单张失败不会中断整批：会打印 `[warn] 推理失败 <图片>: <原因>` 并计入失败数，其余图片继续标。

**坐标怎么导出成文件？** `python3 -m autolabel coords <数据集>`，或界面右上角点「坐标 CSV / 坐标 JSONL」。详见 `03-坐标文件说明.md`。

**重复点了很多次导出，会不会堆一堆目录？** 不会。界面导出先算一份内容指纹（收了哪些图 + 标签原文 + 导出参数），和 `exports/` 里最近一份一样就直接复用，提示语会写「标签没有变化，已复用上次导出」；只有你真的改过标签或换了导出范围才会生成新目录。历史上已经堆出来的重复目录可以放心删，`exports/` 里每份都是自包含的快照，删掉不影响数据集本身。

**按 `U` 提示「这张图还没有可撤销的修改」是什么意思？** 就是字面意思：这张图从自动标注结果以来你没保存过任何改动，没有历史快照可回退，不是报错。撤销是逐层往回退的，连续按会一级一级退到自动标注的原件。

**导出的文件到底在哪？** 在 `<数据集>/exports/<时间戳>/`（提示词标注的是 `<时间戳>-detect/`）。界面上不用记：导出成功后会自动帮你打开一次目录，模块页顶栏下面也常驻一行「上次导出」写着完整路径，点 **在访达中显示** 直接定位（重新打开也行），点 **复制路径** 则能拿去终端 `cd`；不知道数据集在哪就看 `/api/dataset` 的 `root` 字段，门户和复核页的地址栏旁边也写着。注意数据集放在 `/tmp` 下时访达默认看不到，重启电脑还可能被清掉，长期用建议放项目里的 `datasets/`。

**要直接拿去训练的那份数据集在哪导出？** 界面右上角坐标按钮旁边的「YOLO 训练集」，或 `python3 -m autolabel export <数据集>`（提示词标注用 `autolabel prompt <数据集> --export`）。产物是目录不是文件，界面点完会在提示里给出路径，直接 `yolo pose train data=<路径>/data.yaml`。库里还没有骨骼标签时会直接告诉你先去跑标注，不会导出个空目录。

**网页上传和命令行导入怎么选？** 补几段视频、几十张图用网页最省事；几十万张批量导入或要精细控制参数时用 `import` / `video` / `auto`，两条路是同一套流水线。

**上传后界面没反应 / 没有新图？** 看上传弹层的日志和顶部绿色进度条。后台是单任务串行的，前一个没跑完会排队；任务完成后列表才刷新。

**上传的原始视频留在数据集里吗？** 不留。文件先放 `.autolabel/uploads/`，任务成功后自动删除；抽出的帧保留，并带 `video` / `time_sec` 指回原视频。上传到一半强杀进程 / 断电的话，留下的临时文件由下次启动复核服务时清掉（超过 24 小时没动过的都算残留），启动日志会写明清了几个、释放了多少 MB。

**抽帧后入库数量比抽出帧少很多？** 默认感知去重（dHash 距离 ≤ 5）丢弃近重复帧。想全留：命令行 `--video-dedupe none`，界面勾「保留近重复帧」。

**标注进行中能改图吗？** 界面会临时锁住接受/驳回/新增/撤销。底层用的是"重读磁盘 + 按图合并"，即使忘了锁也不会整体覆盖索引，但同一张图同时改仍可能互相覆盖，建议等任务结束。

**导出的 symlink 能训练吗？** 能，ultralytics 正常跟随软链。换机器用 `export --mode copy`。

**人工改过点后 index 里的 score 为什么没变？** YOLO 标签不存模型置信度，改点后无法反推分数，系统沿用历史分值。判断该不该复核请看 QC 标记，不要只看 score。

**关键点左右反了怎么办？** 姿态标注页的**待办清单**会把贴边、被标遮挡、置信度偏低的点按「先修错的、再看可疑的」排好并编号（画布上是同一个号），按 `J` 逐条跳过去看；`limb_length_mismatch` 标记专治左右互换，选中后按 `0/1/2` 纠正或直接拖动。翻转变换的左右索引互换有回归测试兜底。

**想换自定义骨架（比如 9 个点）？** 目前固定 COCO-17，`yolo_pose.py` 的 `COCO17_KEYPOINTS` / `COCO17_FLIP_IDX` / `COCO17_SKELETON` 是唯一事实来源；改这三个常量并同步 `init --num-keypoints`，`export` 会自动写对应的 `kpt_shape` 与 `flip_idx`。

**MPS 报错或结果异常？** 加 `--device cpu` 复核一遍；A/B 对拍时用 `--no-flip` 排除翻转融合带来的差异。

**为什么 `v=1` 的点也被训练了？** ultralytics 用 `kpt_mask = v != 0`，`1` 也算监督目标。只想训高置信点：`--visibility-policy binary`，或把遮挡点在界面里按 `0`。

**界面打不开 / 端口被占？** `python3 -m autolabel review <数据集> --port 9000`。本工具默认只监听 `127.0.0.1`，不要公网暴露（无鉴权）。

**权重下载卡在下载不动？** `models/` 下放同名权重即可离线使用；默认已在 `models/yolo11n-pose.pt`、`models/yolov8n-pose.pt`。

## 素材明明上传成功了，重启服务后界面却空了

导入/标注跑到一半被打断（关掉终端、Ctrl+C、强杀进程、断电）时，图片副本可能已经写进 `images/` 而索引还没保存，界面上就像素材凭空消失，批次还会一直显示"标注中"。

现在复核服务启动时会先按库做一次 **migrate**（老布局升级成两库，已是分库布局直接跳过），再**逐库对账**：把这些图片按磁盘补回它自己库的索引（挂到那个中断的批次上，状态仍是未复核），并把无人认领的"标注中"批次判定为 **已中断**；工作台顶部会显示黄色提示条，写清补回了几张、判定中断几个批次。启动日志里也有同一条 `[warn] 启动对账：…`。某个库还在标注时，另一个库的对账不会把它刚落盘的孤儿素材抢走。

- 中断批次里**没跑完**的那部分图片确实没入库，重新上传一次即可。
- 用 `autolabel batches --delete <批次ID> --keep-files` 删批次时留在磁盘上的文件是刻意保留的，对账不会把它们当成孤儿重新长回来。
- 提示条里写「N 条记录的原图已不在磁盘上」时，是索引有记录但文件被外部删掉了，按需在界面重新导入。

## 用命令行导入的图片，复核界面看不到？

不用重启服务了。刷新时 `GET /api/dataset` 会比对**两库索引**（`.autolabel/index.json` 与 `.autolabel/objects/index.json`）的修改时间与大小，变过就重读（之前只重读内存里那份，`autolabel import` 导进来的图会一直显示 0 张）。同理，另一个终端里跑的 `autolabel label`、外部脚本改索引，界面刷新后都能看到。反过来说，**别在服务运行时手工编辑 `index.json`**，可能被服务下一次保存覆盖掉。

## 提示词标注和姿态标注什么区别？会不会互相覆盖？

两个**独立的库**，不只是各写各的目录：姿态库写 `labels/` + `.autolabel/index.json` + `.autolabel/batches.json`（人体 + COCO-17 关键点，YOLO-pose 权重），提示词库写 `prompt_labels/` + `.autolabel/objects/index.json` + `.autolabel/objects/batches.json`（任意物品检测框，多模态大模型），连原件和撤销快照都分开（`objects/originals/`、`objects/history/`）。索引键也各一半：姿态库只有 `status` / `objects` / `flags`，提示词库只有 `prompt_status` / `prompt_objects` / `prompt_flags`，接受/驳回、删除、撤销都互不影响。

导出同样是两套：`autolabel export` 出 `yolo pose train` 数据集，`autolabel prompt --export` 出 `yolo detect train` 数据集，坐标文件也分骨骼和检测框两份，别混用。详见 `09-提示词标注.md`。

## 两个模块各自上传，主页能一起管吗？

能。主页底部的「批次管理」把两个库的批次放在一张表里，按模块徽章区分，顶部按模块汇总批数/张数/已标数，右侧下拉框可只看某一个库。每个批次行同时显示骨骼进度和检测框进度：这两列走**跨库视图**（骨骼列取姿态库、检测框列取提示词库），所以行内小计与「看文件」展开的逐张清单永远对得上；顶部统计卡则各算各的库，不会互相掺水。

上传口也是分开的：姿态页右上角「上传素材」（`W`）跑 YOLO-pose，提示词页右上角「导入素材」（`W`）跑多模态检测框，各建各的批次、各写各的标签目录；两边的弹层里都有 **从素材池添加**，另一侧传过的素材直接引用同一份文件即可。

## 只想删传错的某一张图

不用整批删。主页「批次管理」里点该批次的 `看文件` 展开逐张列表，行尾 **从本库移除** 删单张，行首勾选可一次删多张（底部按钮随之变成「从本库移除所选（N 张）」）。删前照样在 `.autolabel/deleted/` 写快照，坐标文件与 QC 报告随之重算；某批被删空时那条批次记录会自动消失，不会挂着 0 张的空行。

注意删的是**这个库里的引用**：`images/` 的素材文件和另一个库的标注都不动（行尾那枚「两库共用素材 / 仅本库素材」就是提示这件事）。要连素材一起清干净，勾上底部 **「连素材文件一起删（两个库都移除）」**，按钮会变成「删素材」，两个库的引用与磁盘文件一起清。

批次还在标注中时删不掉，先到对应模块点「清除任务」。命令行等价：`python3 -m autolabel batches <数据集> --delete-images images/a.jpg --lib objects [--mode lib|purge]`（可重复给多个）。

## 刚画的框能撤销吗？

能。第一次在一空白图上画完保存后按 `Z`（或 `U`），会退回"一个框都没有"的空白状态——首次保存前系统会先留一张空白快照，之前这种情形会提示"没有可回滚的历史版本"。备份在提示词库自己的目录里：`.autolabel/objects/originals/`（模型原始标注）与 `.autolabel/objects/history/`（最近若干次修改快照），姿态标签走 `.autolabel/originals/` 与 `.autolabel/history/`，两库的撤销互不干扰。

框列表里也能逐个删：点某一行右侧的删除，或选中框按 `X`。删错的框被撤销救回来后，人工标记（`manual`）也会一起回来。

## 按 `⌘F`、`⌘D`、`⌘1` 的时候标注页会自己翻页？

以前会。翻页 / 接受 / 驳回这些快捷键只看按键、不看修饰键，于是 `⌘A`（全选）当成 `A` 翻上一张、`⌘D`（收藏）翻下一张、`⌘F`（页内查找）顺手跳到下一张带标记、`⌘J`（下载）跳待办、`⌘B`（书签栏）弹出批次管理、`⌘M` 直接跳到模型管理页、`⌘1/2/3`（切标签页）还把关键点可见性改了。现在两个标注页都只接 `⌘K`（命令面板）和 `⌘Z`（撤销），其余 `⌘` / `Ctrl` 组合原样交回浏览器。

顺带把撤销的键理顺了：`⌘Z` 现在就是撤销（和 `U` 同一个动作），裸 `Z` 仍是适应窗口，速查表和页面上都写了两条路。

## 复核界面突然一片空白，也不说为什么

多半是**这张图在另一个标签页里被删掉了**（或者刚跑完按批次删除）。以前前端不看接口返回的状态码，把 `{"error": "..."}` 当成标注数据用，结果是画布一片白、右侧面板空白、控制台里一行 `TypeError`，只有关掉重开才知道发生了什么。

现在读不到某张图的标注会直接把接口那句中文说出来：画面下方提示「读不到这张图的标注：未知对象: images/a.jpg」并弹一条横幅，队列与进度照常刷新，按 `→` 继续翻下一张就行。首屏拉不到数据集时同样会写明白，而不是白着一页。

## 换了模型或 `--imgsz` 重标，我手改过的骨骼会被冲掉吗？

不会。骨骼库的重标判定是**逐张**看的：状态是「已接受」（`approved`）或「已修改」（`edited`，手改过骨架但还没点接受）的图根本不进重标队列，标签文件一个字节都不动；`label` 的收尾输出会写一行「人工已复核 N 张未覆盖（连它们一起重标加 --force）」。

以前是真的会被冲掉：参数一变就整批重标，人工接受过的图也被重新推理、标签直接覆盖，而复核状态还留在「已接受」——它不会再出现在复核队列里，等于悄悄丢了，只能去 `.autolabel/history/` 的快照里捞。

要连人工结果一起重标就加 `--force`，这时人工标签会被模型结果替换、状态退回未复核，得重新过目一遍。另外参数改动后中断再重跑，中断前已经按新参数标好的图不会再标一遍（以前整批从头再来）。提示词库那条路径的规则见下一条。

## 批量重标会不会把我手工画的框冲掉？

默认不会。批量提示词标注除了跳过同签名的图，还跳过两类"人碰过"的图：已点过接受的（`prompt_status=approved`）、手动画过框的（`prompt_manual>0`）。汇总里会报「人工保护 N 张」。起因是实测踩过：模型对某张图回了 0 个框，把人复核半天的框直接抹平，索引里还留下指向不存在框的人工标记。

勾「覆盖已有框」（命令行 `--overwrite`）才会连这些一起重标，此时人工标记、人工框下标、类别号都会按模型结果重写，复核状态退回「已编辑」，得重新过目一遍。

## 同一批素材两个模块都要用，会占两份磁盘吗？

不会。`images/` 是**共享素材池**，同一帧只落盘一次，两个库各持一条引用：

- 跨库导入时若指纹命中池里已有的文件，直接复用，命令行与批次备注里写「复用素材池 N」；
- 已经传过的一侧不必重传：另一模块的上传弹层里点 **从素材池添加**（或 `autolabel pool <数据集> --lib objects --add images/a.jpg`），把池里的图认领进本库，不复制文件；
- 素材文件要等**两个库都不再引用**才真删。只想撤一个库，用默认的「从本库移除」，对面照常能看。

`autolabel status` 会写清「素材池 N 个文件 · 两库共用 M · 无人引用 K」，`K` 不为 0 说明有素材被漏在池外（一般是对账或外部拷入造成），把它认领进需要的库即可。

## 老数据集怎么升级到两个库？要重装吗？

不用重装也不用重标。`python3 -m autolabel migrate <数据集>` 会把旧版单索引里的 `prompt_*` 条目、检测框原件与撤销快照拆进 `.autolabel/objects/`，并把批次按归属归位到两张批次表；姿态库的索引位置不变，所以标签和骨骼记录一个字节都不用动。命令**幂等**，重复执行只回一句「已经是分库布局，无需迁移」；复核服务启动时也会自动做一次。只做骨骼标注、从没跑过提示词标注的老数据集同样会被处理：没有 `prompt_*` 可搬时补一本空的 `.autolabel/objects/index.json`（输出写「新建 …」）。以前缺了这本索引，这种数据集的复核网页会直接打不开。迁移前若你想留底，直接复制整个数据集目录即可（都是本地文件）。

## 提示词标注的字段名为什么不能用中文？

字段名要同时进 `data.yaml` 的 `names` 和模型提示词，还得被模型原样回报，所以只允许 ASCII：英文字母开头，可含字母/数字/`_`/`-`，≤32 字符。中文名放「显示名」（≤40 字符），界面和坐标文件的 `display_name` 列用它。

描述提示词（`prompt_hint`）随便写中文，这才是决定标注质量的部分，上限 600 字符。

## 删掉的字段，类别号为什么不复用？会不会串类？

`class_id` 分配后永不复用：删掉 0 号字段，下一个新字段拿的是 4 号而不是 0 号。这样历史标签里残留的 0 号不会因为新字段顶上来而串成另一个意思。代价是类别号可能不连续，而 YOLO 要求 `names` 从 0 连续递增——导出时会自动重映射成连续的 `0..N-1`，并在 `data.yaml` 注释里写明映射，训练侧不用管。

字段被删但它的框还在磁盘上时，界面「字段管理」会提示"孤儿类别号"，勾「连带删除框」或命令行加 `--drop-boxes` 清掉。

## 上传大文件报「网络错误」，是没网还是超限？

多半是**超限**，以前这句提示确实容易骗人。服务端遇到超过 `--max-upload-mb`（默认 1024 MB）的文件时会先把请求体读干净再回 413，界面于是能显示「单个文件超过 1024 MB 上限」；以前是立刻断开连接，浏览器还在往里写剩下的几 MB，只能报断链。真要传更大的文件就调 `review --max-upload-mb 4096`，或者更省事：命令行先 `autolabel video <数据集> <视频> --start/--duration` 分段抽帧，别把几百 MB 塞进浏览器。

界面拖很多张图没反应时也看一眼这个数字——单文件上限是按**一个文件**算的，不是一次选择的总量。

## 两次导出的验证集为什么不一样？为什么我加图之后指标变了？

以前是真的会换人：切分是「整表 shuffle 取前 N 张」，名次取决于当次一共有多少张，补 9 张图重导，原来的验证图可能掉进训练集——**同一帧既参与训练又参与验证**，指标虚高且两次不可比。

现在按 `(seed, 图片相对路径)` 的哈希分桶决定归属，一张图进不进 val 只跟它自己有关：数据集怎么长，老验证集成员都不动，比例照样按 `--val-ratio` 收敛。想让换一批人就直接换 `seed`（`POST /api/export` 的 `seed` 参数），换完仍然可复现。

顺手一个自查：如果你手上那份导出数据集是这次改动之前导的，而你又中途加过图，重导一次再对比指标更稳妥。

## 抽帧一直转圈不出结果，也不报错

现在不会无限等了：`ffprobe` 60 秒没返回就当成「元信息未知」继续跑，抽帧按片段长度推导超时（5 分钟起、最长 1 小时），超时抛出「抽帧超过 N 秒被中止，视频可能损坏或过长」，已经把抽出来的帧保留在临时目录之外不入库。低配机器跑 4K 长视频嫌不够，用环境变量放宽：

```bash
AUTOLABEL_FFMPEG_TIMEOUT=7200 python3 -m autolabel video datasets/xxx clip.mp4
```

真卡住的常见原因是文件本身损坏或所在磁盘/网络盘失联，先 `ffprobe 文件名` 在终端试一下最快。

## 命令行现在只回一行 `[error]`，是不是坏了？

不是，是故意收成这样的。以前路径打错、批次 ID 写错会得到一屏看不懂的 Python 栈，真正有用的那句（「数据集还没初始化」）埋在最后一行。现在这类**你自己就能改对**的错误统一是一行中文说明 + 退出码 1：

```
[error] 数据集不存在或缺少索引，先跑 autolabel init <数据集>
```

怀疑是软件本身的毛病、想看栈的时候，加个环境变量再跑一次，完整栈照常贴出来：

```bash
AUTOLABEL_TRACEBACK=1 python3 -m autolabel status datasets/xxx
```

## `import` 显示成功，批次列表里却没有批次，图去哪了？

两种情况，都不是丢图：

- 输出写的是「扫描 N 张，没有新图入库」——这些图**早就在素材池里**（精确或近似去重命中），这次没有新增。想把已入库的图重新标注用 `autolabel label <数据集> --force`，不用重复 import。
- 上面还有一行 `[warn] 路径不存在，跳过: ...`——路径打错了。所有源都不存在时现在直接报错退出，不再「成功导入 0 张」；相对路径记得写成绝对路径，或先 `cd` 到它们的上级目录。

以前这两种情况都会在批次表里留下一个 0 张的空批次，看着像有一批数据、其实什么都没有；`auto` 更糟，会继续往下标注并导出坐标，产出一堆空文件。

## `--conf`、`--val-ratio` 这类数字能随便填吗？

不能，现在会当场拦下来。比例类（`--conf` `--iou` `--visible-conf` `--occluded-conf` `--scene` `--val-ratio`）必须在 0 和 1 之间；`--imgsz` `--max-side` `--max-frames` `--top` 等必须大于 0；`--port` 在 1~65535；`--jpeg-quality` 在 1~100。`--limit 0`、`--start 0` 这种有实义的写法照样放行（0 = 不限制 / 从第 0 秒开始）。

完整取值表见 `02-命令行参考.md` 的「参数取值范围与报错约定」。界面导出走同一套取值：`验证集比例`、`背景图比例上限` 必须在 0~1，`随机种子` 要填整数；0 是合法值（`val_ratio=0` 整库当训练集、`max_empty_ratio=0` 一张背景图都不要），不会被悄悄改回默认值。

## 导出出来的训练集，张数比库里少了一大截？

不是丢图，是**没符合导出条件**，现在会逐张告诉你原因：

- **状态被剔**：默认范围 `剔除已驳回（含未复核）` 只排除 `rejected`；选 `只要已接受 / 已修改` 时未复核的帧也会被排除。
- **背景图比例**：无人图（空标签）默认最多占 15%（`--max-empty-ratio` / 界面参数），正样本 100 张时最多收 17 张背景图，剩下的按上限压掉。这是故意的——负样本淹了正样本，模型会学成"什么都不是"。
- **缺标签 / 坏标签**：从没标过、标签文件不存在的帧不进训练集；某一行字段数不对（手改过 `labels/` 容易碰到）也只跳过那一张，原因里带着 `文件:行号`，改完整批就能导。`qc/stats.json` 里的 `missing_labels` 与 `bad_labels` 各算各的。

去哪核对：命令行导出后看那行「剔除明细」，或打开 `exports/<时间戳>/manifest.json` 的 `skipped`（一张一行、带原因）、`counts.empty`（收进来的背景图）与 `counts.empty_dropped`（被压掉的背景图）。一张都不符合条件时会直接报错「没有符合条件的样本可导出（status=rejected 2 张）：想连被驳回的帧一起要，命令行加 `--include-all`，界面里把导出范围改成「全部帧」」，不再丢个空目录说成功。括号里是少掉的原因，冒号后面按**这些原因**给对应的出路——缺标签就让你去跑标注（换导出范围没用），背景图被压上限就给 `--max-empty-ratio`，别照着上一句的提示瞎试。

**选中的帧标签全坏也会拦下来。** 个别行字段数不对只跳过那一张，其余照导；如果这次收进来的帧**每一帧**都读不通，报错「选中的 N 帧标签全都读不通，一张都没导出」并清掉那个空目录——以前这种情况会照样打一行 `[ok] 导出`，你得等到 `yolo pose train` 才发现训练集是空的。

## 门户的「等你复核」和 `qc` 报告的「待复核」对不上？

现在四处是同一个口径：**还没定论的帧** = 既没点接受、也没点驳回（含改过但没接受的）。门户的数字直接取后端 `/api/dataset` 的 `review` 字段，两个复核页的默认队列、`qc report` 的「待复核」、启动日志里的「等你复核 N 张」都从同一条线算，不会再出现"同一个词三个数"。

已接受 / 已驳回的帧不再占用优先复核清单（已经排除出训练集的东西不该反复挡在第一个）。想连已定论的一起复盘：`autolabel qc <数据集> --include-reviewed`。

## 按错 `Q` 接受了废帧，除了撤销条就没别的办法？

撤销条（5 秒）点撤销或按 `U` 最直接：它撤销的是**刚才那一帧的这次接受 / 驳回**，状态退回原样并把画面跳回那一帧。撤销条收起来之后也来得及——筛选切到「已接受」或「已驳回」，选中那帧再点另一个按钮（或按 `Q` / `E`）就是改状态。注意此时按 `U` 撤销的是**当前帧的一次坐标修改**，不是刚才那次定论。

## 「两个模型结论一致」为什么也算待确认？

不算了。这条是**正向标记**（后端权重是负的 -1.5，意思是两个模型结论一致、更可信），以前前端只看"有没有标记"，把它也算进红点、`待确认 N 处` 和 `F` 键跳转，结果最可信的帧反而排在队列里催你去看。现在它排在标记区最后、染成绿色，鼠标悬停写着"加分项，不占待办"。哪些标记算正向由后端下发（`/api/dataset` 的 `positive_flags`），前端不再自己猜。

## 顶栏那个 `v1.2.3` 是什么？GitHub 上有新版本会怎样？

是当前版本号，点开直接进 GitHub 仓库（`https://github.com/windinchen/autolabel`）。「关于」里还写着开发者 `windinchen`，点开设者的 GitHub 主页。四个页面顶栏都有，数字全部来自 `autolabel/version.py`——界面上没有写死过任何一个版本号，不会出现"顶栏还挂旧号、命令行已经是新版"。

GitHub 上发布了更新的版本时：顶栏徽标染成琥珀色带个圆点，同时顶栏下面挂一条「GitHub 上有新版本 v1.2.4（当前 v1.2.3）· **查看更新** · **知道了**」，启动日志也会补一行。点**知道了**按版本记住，同一版不再重复提；GitHub 真出了下一版还会再来。

## 界面上说 GitHub 有新版本，怎么真的升？

提示条的**查看更新**直接到发布页，取代码这件事仍要你自己做（`git pull` 或下 release 包）——软件**不覆盖自己的代码**，只负责告诉你可以升了。升完重开 `review`，启动日志与顶栏徽标都是新版本号。

命令行 `python3 -m autolabel version` 一次看全：当前版本、开发者、仓库与发布页、GitHub 最新版、上次检查时间、缓存文件在哪；加 `--check` 立刻联网重查（界面「检查更新」走的是同一条路）。

版本号**只有一处**：`autolabel/version.py` 的 `VERSION`。自己维护这份代码要升版本，用 `python3 -m autolabel version --bump`——按约定日常改动只 **+0.01**（`1.2.2 → 1.2.3`），`--bump minor` / `--bump major` 留给特意安排的大版本。它只改那一行，并把提交打 tag 的命令打给你。

## GitHub 上的版本比本地还旧，是不是坏了？

没坏，也不骗你。这种情况下提示写「本地是开发中的版本」，**不弹**「有更新」——你跑的是没发布过的检出（比 release 新），弹提示只会让人白点一次。判定很简单：只有 GitHub 的版本号**严格大于**本地才提示更新，`v1.2` 与 `1.2.0` 视作同一个版本。

## 机器不联网，会不会为查版本卡住？

不会。查版本在 `review` 启动后丢后台线程做，结果缓存 `~/.autolabel/update.json`（12 小时内不再联网），页面打开只读缓存；单次请求 2.5 秒超时。取不到就照说「没查到」并带原因，**不会**假装"已是最新版"。彻底不想联网就设 `AUTOLABEL_OFFLINE=1`，「关于」里会写「已按离线设置跳过检查」。

## 我的电脑有 NVIDIA 显卡，怎么让标注走 CUDA？

界面 `⌥S` 打开**系统设置**，右半「推理算力」里选 **NVIDIA 显卡（CUDA）**；命令行等价 `python3 -m autolabel settings --device cuda`。面板打开时会现探这台机器，能用的话直接把显卡型号列出来（`NVIDIA GeForce RTX 4090`），用不了会写明原因。

前提是装的 PyTorch 本身带 CUDA。系统设置分得清这两种「用不了」：`这个 PyTorch 不带 CUDA（装的是 CPU 版或 macOS 版），换显卡也还是 CPU`——这种要重装 CUDA 版 torch；`没检测到可用的 NVIDIA 显卡，检查驱动或 nvidia-smi`——这种是驱动/硬件层面。

默认档位是**自动选择**：有 N 卡用 CUDA，其次 Apple 加速，最后 CPU。所以严格说 Linux + N 卡的机器不改设置也会自己走 CUDA，`autolabel settings` 会把「本次会用哪块」打出来。

## 选了 CUDA 但这台机器好像没生效？

按这个顺序查，三处都看得见结果：

1. `python3 -m autolabel settings` —— 看存的是不是 `cuda`，以及这台机器识别到几张卡；
2. 标注启动日志 —— `加载模型 models/xxx.pt -> device=0`，`device=0` 就是走了第一张 N 卡；
3. 有没有 `[warn] …不可用（原因），本次改用…` —— 有这行就是**故意降级**了，不是没生效。

再往上游查一步：`python3 -c "import torch; print(torch.cuda.is_available(), torch.version.cuda)"`。第一个是 `False` 而 `torch.version.cuda` 是 `None`，说明装的是不带 CUDA 的 torch 包。

## 半精度加速开了没变快？

半精度只有 NVIDIA 显卡真的提速。在 CPU 或 Apple 加速（MPS）上开半精度，软件会直接挡下来并打一行 `[warn] 半精度在 cpu 上没有加速（只有 NVIDIA 显卡支持），本次按普通精度跑`——不是没生效，是压根不支持还硬开着会更慢。ultralytics 自己也是这么回退的，我们只是先把这句话说明白。

## 中途换了推理设备，之前标好的几千张会重跑吗？

不会。`device` 与 `half` 只改快慢、不改标成什么样，特意**不计入**断点续跑的参数指纹。改成 `--imgsz`、`--conf`、`--no-flip` 这些真正影响结果的参数才会触发重标，这时界面与命令行都按「参数变了」处理。

## 命令行写了 `--device cpu`，会被系统设置里的选择改掉吗？

不会。优先级是：命令行 `--device` > YAML `--config` 里写明的 > 系统设置 > 内置默认（`auto`）。系统设置只在前两者都没写时兜底——家目录里一个文件不该能改掉你命令行明确写的东西。

## 白天/夜晚和字号去哪了？原来在 `⋯` 菜单里的外观设置呢？

收进**系统设置**了（`⌥S`，或 `⋯` 菜单 → 系统设置）。以前白天 / 夜晚、字号摊在 `⋯` 菜单底部，换推理设备还得去命令行，两件事各在一处迟早对不上；现在同一个面板左半外观、右半算力，四个页面同一个入口。

存法有意区分：外观是「我这台电脑怎么看」，存浏览器 `localStorage`，换浏览器要重设；推理算力决定标注算在哪，存 `~/.autolabel/settings.json`，换浏览器也认这份。两者都不写进数据集目录。

`⌥T` 切昼夜、`⌥=` / `⌥-` 调字号照旧可用，`⌘K` 搜「外观」「字号」「推理设备」都能直达。

## 点录制没反应 / 摄像头一直转圈？

九成是页面不算「安全网页」。浏览器只在 HTTPS（或 `localhost`）下开放摄像头，HTTP 页面点录制只会拿到「权限被拒绝」。

1. 地址栏确认开头是 `https://`，完整地址 `https://localhost:8765/`；
2. 没证书就做一次 `python3 -m autolabel ca`，之后重起 `review` 自动走 HTTPS；
3. 还不行就看启动日志有没有 `已启用 HTTPS（摄像头可用）`，没有说明证书没加载成功，`autolabel ca --status` 会说是哪一步。

顺带一提：系统设置里选「纯 CPU」只会让标注变慢，跟摄像头无关——摄像头是浏览器那一侧的权限问题。

## 浏览器说「您的浏览器不支持此网站」/ 打不开页面？

服务活着但协议对不上：新版浏览器会自动把 `http://` 升级成 `https://`，纯 HTTP 服务收到 HTTPS 握手就回这么一句。

- 最直接：地址手写全 `https://localhost:8765/`；
- 或者先 `python3 -m autolabel ca` 让服务有证书可加载，再重起；
- 只想用 HTTP（不录摄像头）就 `review --no-ssl`，并且在浏览器里关掉这个站点的「始终使用安全连接」。

端口有没有起来看 `autolabel status <数据集>` 或直接 `curl -k https://localhost:8765/`；起不来就双击 `运行工作台.command`，它会自己查端口、缺证书自己补。

## 证书会不会弹「Chrome 想修改受限制的系统根证书」？

不应该再弹了。根证书现在装进**当前用户**的信任域（`security add-trusted-cert` 不带 `-d`），不要管理员密码、不动系统根证书列表。会弹那种框的是早先装到系统域的做法。

装了之后浏览器还提示不安全，是它缓存了旧的证书状态：**完全退出浏览器**（不是关窗口）再打开。想清干净用 `autolabel ca --uninstall`，再去「钥匙串访问」搜 `AutoLabel Local Dev Root CA` 确认没有残留。

## 我在系统设置里换了显卡，怎么没换过来？

看面板顶部有没有「推理设备被启动参数指定为……」。带 `--device` 起的实例（比如 `review --port 8766 --device cuda`）**以启动参数为准**，面板里改了只对其它实例生效——这是给「一块卡开一个实例」准备的，不是 bug。

要改全局就用 `autolabel settings --device xxx`，或者不带 `--device` 重起实例。

## 两块显卡能同时干活吗？

能，一个实例一块卡：

```bash
python3 -m autolabel review datasets/vid --port 8765 --device cuda:0
python3 -m autolabel review datasets/vid --port 8766 --device cuda:1
```

启动参数只喂给那一个进程，不会去改写 `~/.autolabel/settings.json`，两个窗口各标各的互不干扰。不想敲命令就 `PORT=8766 DEVICE=cuda ./运行工作台.command datasets/vid`。

同一份数据集建议只有一个实例在写标签：两个窗口同时改**同一张图**时后保存的会盖掉先保存的。两块卡分开跑两个数据集最省心。
